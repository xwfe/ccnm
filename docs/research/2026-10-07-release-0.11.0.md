# 发版 v0.11.0，日用两台换装（2026-10-07）

用户要求把 P62 完成后列的四件事"依次实施"：P70（F25/F26）、P71（受管 Codex 补命令审批）之后，发版并把日用两台换成发布版。

## 1. 版本号

**0.11.0，不是 0.10.2。** 这一版有用户看得见的行为变化（受管 Codex 交互会话开始在每次 `exec_command` 前问人，P71），还新增了 CLI 参数 `ccnm workspace add --agent-node`（P69），按 0.x 的惯例升次版本号。其余是 P62 收尾查出来的修复（P68 监督进程丢失与原始输出丢失、P69/P70 doctor）。

内部协议号没变（仍是 10），新增的都是可选字段；但两端版本号不同时 doctor 和起会话照样报 `CCNM_E_VERSION`，**两台要一起升**。`ccnm.machine/1`、`ccnm.workspace-mcp/1` 没有改动。

## 3. 日用两台换装

本机（Runtime / Operator，`this = "runtime"`，四个 workspace）与 fodelf（Agent）原来装的是 P68 的构建 `90c93c0f…`（[P68 记录](2026-10-04-p68-supervisor-gone-lost-output.md)第 6 节）。这次换成 release 下载的 macOS 包：按 GitHub 给的 digest 和包里附带的 `.sha256` 两头核对过，再用"新文件 + 改名"盖上去。

| | 本机 | fodelf |
| --- | --- | --- |
| 换之前 | 没有在跑的 ccnm 进程 | 只有 Controller（pid 29110），没有在跑的会话 |
| 备份（这次的回退目标） | `~/.local/opt/ccnm-0.10.1-bebc539/ccnm`（`90c93c0f…`） | 同一路径，另有 Controller 的 plist |
| 之后 | `ccnm 0.11.0`，`e62c697b…` | 同左；`controller install` 后 Controller pid 86933，`ccnm 0.11.0 … Aqua` |

更早的 0.9.0 备份仍在两台的 `~/.local/opt/ccnm-0.9.0/`。

**核对**：本机对四个 workspace（`ccnm`、`xdo`、`xshun`、`gld`）跑 `ccnm doctor` 都是 0 项失败、3 项没查（都是设计上不查的）；两端、Controller、反向 SSH 都报 0.11.0；`Command approval` 是这台日用配置本来就有的 WARN（`allow_unattended_exec`）。零额度冒烟：`ccnm run ccnm --detached` 由新 Controller 起会话，Claude Code 停在输入框，本机起了 `mcp-serve`；不发消息，`ccnm stop ccnm --session <id>` 一次停下，`mcp-serve` 退出，fodelf 的 `ccnm log` 记"被停止"，四个写锁标记都是 `released`。没有调用模型。

**回退**（两台都要退）：

```bash
install -m 755 ~/.local/opt/ccnm-0.10.1-bebc539/ccnm ~/.local/bin/ccnm.new && mv ~/.local/bin/ccnm.new ~/.local/bin/ccnm
```

fodelf 上同一条，再跑 `~/.local/bin/ccnm controller install`。
