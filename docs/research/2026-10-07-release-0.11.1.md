## 1. 版本号

**0.11.1，补丁号。** 这一版只修 F27（[P72 记录](2026-10-07-p72-approve-for-me-one-session.md)）：v0.11.0 的受管 Codex 交互会话里，有人选过一次 `/permissions` → Approve for me，Codex 把它存进 profile，之后每个会话都不再问人；现在启动参数钉住"审批由人来答"，切换只管当前会话。另有 README 按新用户视角重写。没有新参数、没有新配置项，内部协议号没变（仍是 10）；两端版本号不同时 doctor 和起会话照样报 `CCNM_E_VERSION`，**几台要一起升**。

## 3. 三台换装

都用"新文件 + 改名"盖上去；换之前三台都没有在跑的会话或 `mcp-serve`。

| | 本机（Runtime / Operator，日用四个 workspace） | fodelf（Agent） | hpsrv `ccrun`（P62/P71 测试用的 Runtime 执行账号） |
| --- | --- | --- | --- |
| 换之前 | v0.11.0 发布版 `e62c697b…` | 同左，Controller pid 86933 | v0.11.0 发布版 `c837a445…` |
| 回退目标 | `~/.local/opt/ccnm-0.11.0/ccnm` | 同一路径，另有 Controller 的 plist | `~/.local/opt/ccnm-0.11.0/ccnm`（P71 复验时放的） |
| 之后 | `ccnm 0.11.1`，`fb0a27c8…` | 同左；`controller install` 后 Controller pid 21418，`ccnm 0.11.1 as fodelf … Aqua`，plist 与备份逐字相同 | `ccnm 0.11.1`，`d8422cbf…`，副本在 `~/.local/opt/ccnm-0.11.1/` |

**核对**：本机对四个 workspace（`ccnm`、`xdo`、`xshun`、`gld`）跑 `ccnm doctor`，都是 0 项失败、3 项没查（Codex 原生链、本机工具策略、网络隔离，都是有意不查的），Runtime、Agent、Controller、反向 SSH 都报 0.11.1。零额度冒烟：`ccnm run ccnm --detached` 由新 Controller 起会话，Claude Code 停在输入框，本机起了 `mcp-serve`；不发消息，`ccnm stop ccnm --session f06bdaa3…` 退出 0，`mcp-serve` 退出，`ccnm log` 记"被停止"，四个写锁标记都是 `released`，fodelf 上没有 tmux 残留。hpsrv 上没有 ccrun 的配置（P71 复验收尾时删了），只核了版本号与 sha256。没有调用模型。

**回退**（本机与 fodelf 要一起退）：

```bash
install -m 755 ~/.local/opt/ccnm-0.11.0/ccnm ~/.local/bin/ccnm.new && mv ~/.local/bin/ccnm.new ~/.local/bin/ccnm
```

fodelf 上同一条，再跑 `~/.local/bin/ccnm controller install`。hpsrv 以 ccrun 跑同一条。
