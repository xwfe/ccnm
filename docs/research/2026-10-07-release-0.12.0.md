# 发版 v0.12.0，三台换装（2026-10-07）

P74（Linux 当 Agent Node）完成后，用户要求"发 v0.12.0 并换装三台"，中途加了"完善更新文档"，换装前又定了"清理备份和回退，dogfood 随时大改，不需要这些"。做法与 [v0.11.2](2026-10-07-release-0.11.2.md) 相同，这里只记不同的地方。

## 1. 版本号

**0.12.0，次版本号。** 新能力是 Linux 能当 Agent Node（[P74 记录](2026-10-07-p74-linux-agent.md)）：Controller 在 Linux 上装成 systemd 用户服务，同一个 `linux-x86_64` 包既能当 Runtime 也能当 Agent。macOS 两端的行为没有变。内部协议号没变（仍是 10），几台要一起升。

## 4. 三台换装

照运维手册新写的"用发布包升级"做，**不留备份**：用户定 dogfood 期间不需要回退目标，换装前把三台 `~/.local/opt/` 下所有 ccnm 旧版本（0.8.0 到 0.11.2、P62 候选构建）连同 fodelf 的 plist 备份都删了；运维手册的回退相应改成"装上一版的发布包"。hpsrv ccrun 的 `~/.local/opt/codex-0.154.0` 是钉住的 Codex，不是 ccnm 备份，留着。

| | 本机（Runtime / Operator，执行账号就是自己） | fodelf（Agent） | hpsrv `ccrun` |
| --- | --- | --- | --- |
| 换之前 | v0.11.2 `67ebe312…` | 同左，Controller pid 62225 | v0.11.2 `713909c5…` |

**核对**：四个日用 workspace（`ccnm`、`xdo`、`xshun`、`gld`）的 `ccnm doctor` 都是"可以用了（3 项不查）"、退出 0，0 项失败、0 项没查；Runtime、Agent、Controller、反向 SSH 都报 0.12.0。零额度冒烟：`ccnm run ccnm --detached` 由新 Controller 起会话，Claude Code 停在输入框、工具已连上，本机起了 `mcp-serve`；不发消息，`ccnm stop ccnm` 退出 0，`mcp-serve` 退出，fodelf 上没有 tmux 与 Agent 进程残留，四个写锁标记都是 `released`。hpsrv 只核了版本号与 sha256。没有调用模型。

## 5. 顺带看到的（没修）

**按项目名停一个没绑 Agent 实例的 workspace，`ccnm log` 里那条会话 10 分钟内显示"启动中"，之后变"没有结束记录"，而不是"被停止"。** 这次冒烟用的是 `ccnm stop ccnm`，前两轮用的是 `ccnm stop ccnm --session <id>`（那两轮记的是"被停止"）。原因在 `work.rs` 的交互停止路径：只有点了会话 id、或者 workspace 绑定了 Agent 实例时才写停止标志（`stopping`）和结局（`exit`）；日用四个 workspace 都是旧写法（`agent_node`），按项目名停时进程照样停干净，但记录不写。交互会话没有监督进程 pid，没结局时先算"启动中"，满 600 秒改算"没有结束记录"。这几行最后一次改是 `94eb7bf`（v0.11.2 以来 `work.rs` 只改了测试），不是 0.12.0 引入的。
