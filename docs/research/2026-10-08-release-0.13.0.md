## 3. 真机验证（零额度）

### 3.1 共用账号（P78）与 skill 钩子（P79）：外部 MCP 经真实 ssh

**拓扑**：fodelf 当外部 MCP Host，跑 `ccnm mcp bridge v013 --mode coding`（临时 Host 配置，只写 `[nodes.runtime] ssh = "xdwmbp"` 和 `ccnm_bin` 指向本机的包装脚本）；ssh 落到本机 `bing`，包装脚本导出临时的 `CCNM_CONFIG` 与 `XDG_STATE_HOME`。临时 Runtime 配置**不写 `runtime_user`，也不写两个 `allow_*`**，workspace 只开 `external_mcp = "coding"`。`bing` 在 admin 组、读得到 Claude 和 Codex 的登录、有 SSH 私钥——正是共用账号会碰到的情况。驱动是一个几十行的 Python MCP 客户端，按顺序调工具；日用配置一个字没动。

workspace 里放的 skill 就是[使用说明](../usage.md#项目自带的-skills)的例子（拦 `push --force`、加载时填当前分支），另加一个 `PostToolUse` 钩子（`echo "post-hook ran as $(id -un) in $(pwd)" >&2; exit 2`）。

**v0.12.0（换装前）**：握手就被拒——

```text
CCNM_E_POLICY:
the runtime is running as bing and does not hold the Agent boundary, so no session is served here:
  - No Claude credential: the Runtime identity can access a known Agent credential file or container (private paths withheld)
  - No Codex credential: ...
```

**v0.13.0（换装后），两端都是发布包**：

| 调用 | 结果 |
| --- | --- |
| `initialize` | `serverInfo.version = "0.13.0"`，12 个工具 |
| `exec_command sh -c 'id -un; pwd; ls'` | 执行了：`bing`、workspace 根、`a.txt`；结果里没有"未隔离"那一行 |
| `load_skill guard` | `[1 command(s) this skill runs as it loads were run on this machine]`，正文成了"当前分支：main。"；`[hooks: 2 registered ... PreToolUse Bash, PostToolUse Bash]` |
| `exec_command git push --force origin HEAD` | `isError`：`CCNM_E_POLICY: exec_command was not run: a PreToolUse hook of skill guard stopped it: 别 force push，用 scripts/release.sh`——和使用说明里写的一字不差，命令没执行 |
| `exec_command git status --short` | 执行了；第二个文本块是 `[PostToolUse hook of skill guard: post-hook ran as bing in <workspace 根>]` |

bridge 退出 0，写锁标记 `released`。

### 3.2 `agent_tools` 默认全开（P77）：日用受管会话

`ccnm run ccnm --detached` 由新 Controller 起会话（日用配置没写 `agent_tools`）。fodelf 上受管 Claude Code 2.1.293 的启动参数是 `--tools WebSearch,WebFetch,Agent,TaskStop,TaskCreate,TaskGet,TaskList,TaskUpdate`，会话的 MCP 配置有 `ccnm` 和 `ccnm_agent` 两个 server，`settings.json` 的允许表里五类都在——五项全开。界面停在输入框，上下文 0%，没有发消息。

### 3.3 按项目名停也记"被停止"（P75）

同一个会话用 `ccnm stop ccnm`（不带 `--session`）停：退出 0，本机 `mcp-serve` 退出，fodelf 上没有 tmux 残留，四个写锁都是 `released`。`ccnm log ccnm` 第一行是"被停止"；对照昨晚 v0.12.0 下同样停法的那条（10-07 20:46）是"没有结束记录"。

### 3.4 Linux：发布的二进制跑中立客户端

hpsrv（Debian 13 x86_64），以 `ccrun` 身份用发布包里的二进制（`edcd108c…`）、`v0.13.0` 的测试文件跑 `tests.test_remote_workspace_mcp`：48 条全过，含"不写 `runtime_user` 是共用账号、命令照跑""bridge coding 跑加载时命令、钩子拦下 `rm`""钩子跑着时取消的调用不执行"。`ccrun` 是专用账号，读不到任何 AI 登录，所以"共用账号读得到登录也不拦"这一点只在 3.1 的 macOS 上验到。

## 4. 没验的

- **doctor 在共用账号下的那几行**（`Runtime 执行身份`、`admin 组`、`Claude 凭据` 是"注意"）：受管会话里 Agent 反连 Runtime 用的是 **Agent 自己配置里** `[nodes.runtime] ccnm_bin`，不读 Runtime 配置里的那个，所以不动 fodelf 的日用配置就没法让 doctor 走临时配置；而没有 Agent 的 workspace，doctor 不做执行账号体检。这几行只有离线测试。
- **真实模型**：模型会不会照 `context: fork` 的提示派子代理、被钩子拦下后会不会换做法、真实 Host（Claude Code / Codex）是否把钩子附言那第二个文本块完整交给模型，都没验。3.1 的 Host 是 Python 客户端。
- Linux 上"共用账号读得到 AI 登录"、Codex 受管会话下的 P77/P79。

## 5. 顺带看到的（没修）

- **没有 Agent、只给外部 MCP 用的 workspace，doctor 的结论永远是"还不能用（0 项失败，2 项没查）"**：`Runtime 安全`、`exec_command` 两行写的是"没查"（体检结果只随 Agent 探测回来），而这种 workspace 设计上就没有 Agent。和 P73 处理过的情况同类：设计上查不到的行该是"不查"、不挡结论。
- 想让受管会话用一份临时 Runtime 配置，得在 Agent 那台也另起配置和 Controller（P62 的"并存部署"），因为 `ccnm_bin` 由 Agent 的配置决定。
