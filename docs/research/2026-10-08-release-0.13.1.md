## 3. 三台换装

照运维手册"用发布包升级"，不留备份。换之前三台都没有会话和 `mcp-serve`，fodelf 只有 Controller。

| | 本机（Runtime / Operator） | fodelf（Agent） | hpsrv `ccrun` |
| --- | --- | --- | --- |
| 之前 | v0.13.0 `914c470b…` | 同左，Controller pid 18762 | v0.13.0 `edcd108c…` |
| 之后 | `ccnm 0.13.1`，`15f01f13…` | 同左；`controller install` 后 pid 3768（启动时刻比二进制修改时刻晚 1 秒），报 `listening: ccnm 0.13.1` | `ccnm 0.13.1`，`b6200d31…` |

**和上次不一样的两处**：
- **fodelf 的包是它自己下载的。** 本机 scp 过去传了 60 秒只到一半（6 MB / 9.3 MB），被 `timeout` 掐断，什么都没装。改在 fodelf 上直接从 GitHub 下载，几秒就完成，sha256 核对通过。
- **hpsrv 反过来。** 它自己下载走加速前缀 90 秒只拿到约 2 MB、直连拿不到字节；本机 scp 给 root 只用 2 秒，再 chown 给 `ccrun`、以它的身份核对并安装。

四个日用 workspace（`ccnm`、`xdo`、`xshun`、`gld`）的 doctor 都是"可以用了（3 项不查）"、退出 0。Runtime、Agent、Controller、反向 SSH 都报 0.13.1。

## 4. 真机验证（零额度）

全程没有调用模型。

**P83，没有 Agent 的 workspace 的 doctor**：
- 本机放一份临时配置（只有 `[workspaces.v0131]`，`external_mcp = "coding"`、不写 `runtime_user`，放在 `~/.ccnm-v0131`，经包装脚本导出 `CCNM_CONFIG` 和 `XDG_STATE_HOME`，日用配置不动），对它跑 `ccnm doctor v0131`。
- 结果是"可以用了（14 项不查，原因写在标"不查"的行里）"、退出 0。`Runtime 安全` 和 `exec_command` 两行是"不查"，说明里写明由执行账号在客户端连上时核对。

**P81 和 P82，经真实 ssh 的外部 MCP**：
- fodelf 上放一份 Host 配置（`this = "fodelf"`，`[nodes.runtime] ssh = "xdwmbp"`，`ccnm_bin` 指本机的包装脚本），由一个几十行的 Python 客户端驱动 `ccnm mcp bridge v0131 --mode coding`，按 2026-07-28 开场。
- 第一次因为 Host 配置没写 `this` 被 `CCNM_E_CONFIG` 拒，补上后结果如下：

| 调用 | 结果 |
| --- | --- |
| `server/discover` | `supportedVersions` 含 `2026-07-28`，`serverInfo` 0.13.1，instructions 是"CCNM remote workspace "v0131"…"，`ttlMs 0` / `private` |
| `tools/list` | 12 个工具，`ttlMs 300000` / `private` |
| `prompts/list` | `ttlMs 0` / `private`（本机装着的 skills 都列出来了） |
| `exec_command`（`echo real ssh step one; sleep 12`，带 `progressToken`） | 调用后 10.04 秒收到一条 `notifications/progress`：`running for 10 s · real ssh step one`，token 原样带回；12148 ms 后正常返回 |

bridge 退出 0。

**P81，受管会话经真实 ssh**：
