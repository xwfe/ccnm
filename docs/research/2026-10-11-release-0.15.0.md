## 4. 真机验证（零额度）

全程没有让模型生成任何内容。

**P87，日用配置的受管会话**：`ccnm run ccnm --detached`，由新 Controller 在 fodelf 上起 Claude Code 2.1.296，不发消息。

- 会话目录的 `settings.json` 正好三个键：`autoCompactWindow` 是 300000，`hooks.PreCompact` 是那条 `printf`；claude 的启动参数里 `--settings` 指着它，`--setting-sources user,project,local`。
- 在 fodelf 上经 `/bin/sh -c` 跑这条钩子命令：退出 0、stderr 空，输出 10 行，首尾两行与 `COMPACT_INSTRUCTIONS` 一致。
- 经 tmux 在会话里敲 `/context`（本地命令）：`Auto-compact window: 300k tokens`，`Autocompact buffer: 33k tokens`，即约 26.7 万触发，和零额度实测的"29 万压、23 万不压"对得上。开场底座：系统提示 2.5k、系统工具 8.1k、MCP 工具 8.2k（13 个）、MCP 说明 302、memory 869。
- 随后 `ccnm stop ccnm`：退出 0，本机 `mcp-serve` 没了，fodelf 没有 tmux 和 claude 残留，`ccnm log ccnm` 第一行是"被停止"，四把写锁都是 `released`。

**新发现：tmux 3.7c 下 `ccnm ls`、`ccnm status` 看不见交互会话（不是这一版引入的）。** 上面那个会话跑着时，本机 `ccnm ls` 写"--print 运行中"，两台的 `ccnm status ccnm` 都写"没有在跑的会话"。原因是 ccnm 用制表符分隔 `tmux list-sessions -F` 的字段，而 tmux 3.7c 把输出里的制表符换成了 `_`（本机用临时 socket 复现：`probe-x_1791684774_0`；改用 `|` 分隔则原样）。解析不出字段，会话列表就是空的，只看得到在跑的 `mcp-serve`，于是标成 `--print`。影响只在显示：`stop`、`cleanup`、会话状态判断用的是 `has-session` 加进程检查，不受影响；`attach` 按名字找会话，也不受影响。`tmux.rs` 这段 v0.14.0 起没改过，本机与 fodelf 的 tmux 3.7c 都是 2026-09-04 装的。记进了 `status.json` 的 `observed_gaps`，修法（换一个 tmux 不改写的分隔符，并用真实 tmux 补一条集成测试）等用户定。

三台的临时文件（hpsrv 上 root 的 `/tmp/ccnm-015.*`，fodelf 的下载目录，本机 scratchpad 里的包）都已删掉或留在会话临时目录里。
