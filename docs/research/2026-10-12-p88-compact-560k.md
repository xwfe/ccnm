# P88：受管 Claude 会话的压缩窗口改 56 万，压缩指令配合 Claude Code 自带的总结提示（2026-10-12）

用户 10-12 要求：P87 的默认 30 万改为 56 万；优化压缩时带的信息，让压缩后更好接着干。

## 1. Claude Code 自带的总结提示长什么样（2.1.286 打包代码）

读法同 [P87 记录](2026-10-11-p87-auto-compact.md)第 3 节：`strings -n 6` 导出后找 `Your task is to create a detailed summary of the conversation so far`。

- **总结提示**分三种（整段压缩、只压前半段、只压后半段），结构都一样：先要一个 `<analysis>` 块按时间过一遍，再在 `<summary>` 里写 9 节——1 主要请求与意图、2 关键技术概念、3 文件与代码段、4 错误与修法、5 解决过的问题、6 全部用户消息（安全相关的约束原样保留）、7 待办、8 当前工作、9 下一步（整段压缩时要引用原话）。第 3 节写着 "include full code snippets where applicable"。
- **ccnm 的指令放在哪**：`PreCompact` 钩子的 stdout 接在总结提示后面，前面加一行 `Additional Instructions:`，三种压缩都一样；最后再跟一句"别调工具"。
- **压缩后那条消息**：以 "This session is being continued from a previous conversation that ran out of context" 开头，接总结正文（`<analysis>` 去掉），然后只要不是 diskless 模式，就再加一句 "If you need specific details from before compaction (like exact code snippets, error messages, or content you generated), read the full transcript at: <转录路径>"。
- **压缩后自动补回的东西**：原生 Read 读过的文件（太大的只给一句"用 Read 去读"）、原生 Skill 加载过的 skill 正文（`invoked_skills`）。都按原生工具记账，`mcp__ccnm__read_file`、`mcp__ccnm_agent__load_skill` 的结果不在里面。

## 2. P87 的指令哪里不够

| 问题 | 后果 |
| --- | --- |
| 自带提示第 3 节要完整代码片段，P87 第 7 条说不留文件内容 | 两条互相矛盾，模型只能自己二选一；写成哪样都不可预期 |
| 压缩后原生 Read 的文件会补回来，`read_file` 的不会 | 受管会话压完手里一个文件都没有，得自己猜先读哪几个 |
| `load_skill` 加载的 skill 正文压完就没了，原生 Skill 的会补回 | P87 只要求"点名加载过的 skill"，模型不知道要重新加载才能照着做 |
| 压缩后那条消息指向的转录在 Agent 机器上 | 受管会话禁了原生 Read，`mcp__ccnm__*` 读的是项目机器，那个路径读不到；总结写漏的细节就真丢了，模型还可能白调一次工具去读 |
| 没要求留下花力气才查到的环境事实 | 怎么构建、测试、端口、版本、哪些命令在那台机器上不行，压完要重新摸一遍 |
| "在做什么、做到哪"只要求一句 | 目标、已完成、进行中、卡在哪、下一步散在 9 节里，压完要从头读到尾才拼得出来 |

## 3. 新指令

原文是 `crates/ccnm-core/src/provider/claude/policy.rs` 的 `COMPACT_INSTRUCTIONS`。比 P87 多的：

- 开头说清为什么总结得自给自足：压完只剩它，原生工具的东西 Claude Code 会补回、ccnm 的不会，后面那个转录路径在这台机器上、ccnm 工具读不到。
- 总结最前面一个不超过五行的 Status：目标、做完的、在做的、卡住或等用户的、下一步。
- 第 3 节只引用下一步要用到的那几行代码（改到一半的、要对齐的签名），带路径和行号，其余能重新读。
- 留下花力气才查到的环境事实；写明验证当前工作用哪条命令。
- `load_skill` 的 skill：名字和还在生效的规矩；要照着做先重新加载。
- 点名至多五个压完先读的文件和行号范围。
- 下一步写成一次具体的工具调用或命令；最后一行原样写"下面那个转录路径在跑 Claude Code 的机器上，`mcp__ccnm__` 工具读不到"。

保留 P87 的：用户要求与边界（后来改过的写明哪条算数）、改过的文件和提交、没过的测试与报错原文、后台命令的 `output_ref`、放弃过的做法、不留长输出、压完先 `read_file` 再 `apply_patch`。

没测：真实模型照新指令写出的总结（要花额度）。
