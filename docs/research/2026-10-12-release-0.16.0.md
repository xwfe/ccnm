## 3. 三台换装

照运维手册"用发布包升级"，不留备份。传包和上次一样：本机用核对过的包；fodelf 自己从 GitHub 下载；hpsrv 由本机 scp 给 root，再 `install -o ccrun` 进 `ccrun` 名下、由它自己 `mv`。

**和手册不一样的一处：没停 xdo 的会话。** 换装前 fodelf 的 tmux 里有一个 `ccnm-xdo`（10:55 起、attached，claude pid 29337），本机对应的 `mcp-serve` pid 23001——用户正在用。手册第 1 步要求先停掉所有会话，但停一个正在用的会话会打断用户，不在"三机安装"的授权里，所以只换文件不停它：
- 新文件 + 改名放进去，正在跑的进程留着旧文件，照常用旧代码；
- `tmux.rs` 开头写明 ccnm 的 tmux server 自己占一个进程组，`launchctl bootout` 掉 Controller 带不走正在跑的会话。换完核对：claude 29337、tmux `ccnm-xdo`、本机 mcp-serve 23001 都还在，启动时间没变。

代价是 xdo 换装后到这个会话结束前，新会话起不来：旧版 `mcp-serve` 占着 xdo 的写锁（写锁文件 `held 78e84d44… xdo pid 23001`）。新的 56 万和新指令对 xdo 要从下一个会话起才生效。

| | 本机（Runtime / Operator） | fodelf（Agent） | hpsrv `ccrun` |
| --- | --- | --- | --- |
| 之前 | v0.15.0 `8d98c76d…` | 同左，Controller pid 60270 | v0.15.0 `a37905be…` |
| 之后 | `ccnm 0.16.0`，`cdf1cdb7…` | 同左；`controller install` 后 pid 42536，报 `listening: ccnm 0.16.0`，启动比二进制修改晚 8 秒 | `ccnm 0.16.0`，`b2080cc6…` |

doctor：`ccnm`、`xshun`、`gld` 都是"可以用了（2 项不查）"、退出 0，Runtime、Agent、Controller、反向 SSH 都报 0.16.0。`xdo` 退出 33，唯一一项失败是"远端 MCP 握手"报 `workspace write guard is busy; another session still owns this working tree`，就是上面那个没停的会话；版本那几行同样都是 0.16.0。

## 4. 真机验证（零额度）

全程没有让模型生成任何内容。

**P88，日用配置的受管会话**：`ccnm run ccnm --detached`，由新 Controller 在 fodelf 上起 Claude Code 2.1.296，不发消息。

- 会话目录的 `settings.json` 正好三个键，`autoCompactWindow` 是 560000；claude 的启动参数里 `--settings` 指着它，`--setting-sources user,project,local`。
- 在 fodelf 上经 `/bin/sh -c` 跑 `hooks.PreCompact` 那条命令：退出 0、stderr 空，输出 12 行，sha256 `05f1c0d2ee97f1ea…`，与本地从源码 `COMPACT_INSTRUCTIONS` 加换行算出的一致。
- 经 tmux 在会话里敲 `/context`（本地命令）：`Auto-compact window: 560k tokens`，`Autocompact buffer: 33k tokens`，即约 52.7 万触发，和零额度实测的"55 万压、49 万不压"对得上。开场底座和 v0.15.0 一样（系统提示 2.5k、系统工具 8.1k、MCP 工具 8.2k、MCP 说明 302、memory 869）。
- 随后 `ccnm stop ccnm`：退出 0，fodelf 上这个会话的 claude 没了，本机只剩 xdo 那个 `mcp-serve`，`ccnm log ccnm` 第一行是"被停止"；四把写锁三把 `released`，xdo 那把仍由用户的会话占着。

三台的临时文件（hpsrv 上 root 的 `/tmp/ccnm-016.*`、fodelf 的下载目录和钩子输出）都已删掉，本机的包留在会话临时目录里。

## 5. 没验的

- **真实模型照新压缩指令写出来的总结**：要花额度，没验。
- **xdo 上的新设置**：要等用户当前的 xdo 会话结束、下一个会话起来才生效，到时 doctor 也应恢复"可以用了"。
- **Codex 会话**：这一版没改。
- **tmux 3.7c 下的会话列表**：没修。
