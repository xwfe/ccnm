## 3. 三台换装

同 v0.16.0：照运维手册"用发布包升级"，不留备份；本机用核对过的包，fodelf 自己从 GitHub 下载，hpsrv 由本机 scp 给 root 再 `install -o ccrun`、由它自己 `mv`。用户的 xdo 会话（fodelf tmux `ccnm-xdo` attached、claude pid 29337，本机 `mcp-serve` pid 23001）仍开着，同样没停、只换文件，换完三个进程都在、启动时间没变。

| | 本机（Runtime / Operator） | fodelf（Agent） | hpsrv `ccrun` |
| --- | --- | --- | --- |
| 之前 | v0.16.0 `cdf1cdb7…` | 同左，Controller pid 42536 | v0.16.0 `b2080cc6…` |
| 之后 | `ccnm 0.16.1`，`38e20ef8…` | 同左；`controller install` 后 pid 66051，报 `listening: ccnm 0.16.1`，启动比二进制修改晚 1 秒 | `ccnm 0.16.1`，`33d45cfa…` |

doctor：`ccnm`、`xshun`、`gld` 都是"可以用了（2 项不查）"、退出 0，Runtime、Agent、Controller、反向 SSH 都报 0.16.1。`xdo` 仍是退出 33、唯一失败"远端 MCP 握手"报 `workspace write guard is busy`：写锁文件 `held 78e84d44… xdo pid 23001`，就是那个还在用 v0.15.0 代码跑的会话。

## 4. 真机验证（零额度）

**P89**：拿用户正开着的 xdo 交互会话当样本，换装前后各看一次，没有起新会话、没有调用模型。

| | 换装前（v0.16.0） | 换装后（v0.16.1） |
| --- | --- | --- |
| `ccnm ls` 的 xdo 那行 | `--print 运行中`，工具列空 | `运行中 · 1 个终端`、`4 小时 29 分`、工具"通" |
| `ccnm status xdo` | "没有在跑的会话（--print 的运行不算在内）" | `ccnm-xdo  xdo  1 attached  tools connected  (Background, keychain reachable)` |
| `ccnm status`（全部） | 会话"没在跑"，Runtime 一行标成 `--print 运行` | 会话 `78e84d44 运行中，已运行 4 小时 29 分，1 个终端接着`，Runtime 一行"服务着上面这个会话" |

两台 tmux 都是 3.7c。`ccnm status <ws>` 的写锁行仍是"问不到 Runtime（needs an Agent instance binding）"：日用 workspace 是旧写法 `agent_node`，v0.12.0 起就这样，和 P89 无关。

三台的临时文件（hpsrv 上 root 的 `/tmp/ccnm-0161.*`、fodelf 的下载目录）已删，本机的包留在会话临时目录里。

## 5. 没验的

- **xdo 上 v0.16.x 的新设置**：要等用户当前的 xdo 会话结束、下一个会话起来才生效，到时 doctor 也应恢复"可以用了"。
- **真实模型照 v0.16.0 的新压缩指令写出来的总结**：同上，没验。
