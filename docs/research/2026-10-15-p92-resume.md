# P92：受管 Claude 会话接着上一次的对话开（2026-10-15）

## 1. 要解决什么

用户要求加个参数，能直接接着上次的会话继续。ccnm 起 Claude 时总带 `--session-id <ccnm 会话 id>`，让同一个 id 既是 ccnm 的会话目录名，也是 Claude 的转录文件名。续接不能破坏这一条，所以要先弄清楚 Claude Code 在 `--session-id` 和 `--resume` 一起出现时怎么处理，以及上一次的对话"找不到"时会怎样。

## 2. 怎么测

夹具 [p92-resume.py](probes/p92-resume.py)，零额度：真实 Claude Code 接本机假模型（`ANTHROPIC_BASE_URL` + 假 key），`HOME` 是空临时目录，`sandbox-exec` 只放本机出站。启动参数照 ccnm 的 `launch_cmd`：`--tools ""`、一个冒充 ccnm 的最小 stdio MCP server、`--settings`、`--setting-sources`、`--permission-mode`。每个场景单独起一个 tmux server，命令结束后打印退出码再停住，好抓屏幕。所有场景共用同一个工作目录，和 ccnm 每个 workspace 固定一个工作目录一样。

```bash
python3 docs/research/probes/p92-resume.py <仓库外的新目录> \
    --claude cc-286=/opt/homebrew/Caskroom/claude-code@latest/2.1.286/claude
```

## 3. 结果（本机 macOS arm64，Claude Code 2.1.286）

| 场景 | 参数 | 结果 |
| --- | --- | --- |
| 第一次会话 | `--session-id A`，输入一句带标记的话 | 正常；转录 `projects/<工作目录压平>/A.jsonl` |
| 续接 | `--session-id B --resume A --fork-session`（ccnm 的顺序） | 交互界面正常起来；发给模型的第一条请求有 5 条消息，带着 A 里的标记；新转录是 `B.jsonl` |
| 续接加开场 prompt | `--session-id C --resume A --fork-session "<开场文字>"` | 不用敲字，开场文字自动作为第一条消息发出；请求里同时有 A 的标记和开场文字 |
| 不带 `--fork-session` | `--resume A --session-id D` | 退出码 1：`Error: --session-id can only be used with --continue or --resume if --fork-session is also specified.` |
| 上一次的 id 找不到 | `--session-id E --resume <不存在的 id> --fork-session` | 退出码 1：`No conversation found with session ID: <id>` |
| 设了 `CLAUDE_CONFIG_DIR` | 同"第一次会话""续接" | 转录落在 `$CLAUDE_CONFIG_DIR/projects/<工作目录压平>/<id>.jsonl`，续接同样带着上次的对话 |

一处看着像副作用、其实不是：续接之后 A 的转录多了 689 字节。逐行看，多出来的正好是 `last-prompt`（182 字节）和 `cost-state`（507 字节）两条，是第一个会话被关掉时自己写的收尾记录（夹具在关 tmux 之后立刻量大小，那时它还没写完）。续接本身不改旧转录。

## 4. ccnm 据此怎么做

- `ccnm <项目> --continue`（`-c`）起一个**新**的 ccnm 会话，id 是新的；Claude 的参数是 `--session-id <新 id> --resume <上次的 id> --fork-session`。开场 prompt 放在 `--fork-session` 后面，那是个不带值的参数，prompt 不会被当成 `--resume` 的值。
- "上次"由 Agent 挑：这台 Agent 上同一 workspace、同一 Agent 身份、同一项目根目录的交互会话里，最新的、**Claude 留了转录的**那一次。`--print` 会话带 `--no-session-persistence`，本来就没有转录。
- 转录在不在，按 `<Claude 配置目录>/projects/*/<id>.jsonl` 找：配置目录是 instance 的 profile 或 `claude_config_dir`（即 `CLAUDE_CONFIG_DIR`），都没有就是 `~/.claude`。工作目录怎么压平是 Claude 自己的事，所以每个 project 目录都看一遍；id 是 UUID，同名文件只可能是那一次。
- 必须看转录：开了会话一句话没说就关掉时，Claude 不写转录。拿这种 id 去续，Claude 打印 `No conversation found` 后退出，人接上去只看到终端关了。所以 ccnm 在拨号、建会话之前就查，找不到就报 `CCNM_E_NOT_READY` 并说怎么开新的。
- 已经有会话在跑时照旧直接接上（它就是最新的对话），终端上说明 `--continue` 没另起。
- Codex 不支持，报 `CCNM_E_INVALID_ARGS`。

## 5. 没覆盖到的

- fodelf 上是 Claude Code 2.1.300，没在那个版本上跑这个夹具；`--fork-session` 和 `--session-id` 的约束是 2.1.286 上量的。
- 没跑真实模型；假模型只证明请求里带着上次的对话，不证明模型怎么用它。
- 没在真机上跑 `ccnm <项目> -c`：要发版换装后才行。
