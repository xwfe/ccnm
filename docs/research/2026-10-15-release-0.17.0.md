# 发版 v0.17.0，三台换装（2026-10-15）

用户 2026-10-15 在 P93 查清原因后同意"把 rmcp 升到 3.5.1，连同 P90–P92 一起发版、三台换装"。做法与 [v0.16.1](2026-10-12-release-0.16.1.md) 相同，这里只记不同的地方和结果。

## 1. 版本号

**0.17.0，次版本号**：加了两个命令行参数（`ws add --allow-unattended-exec`、`ccnm <项目> --continue`），起会话的行为也变了（项目机器不肯开就直接报错）。内部协议号没变（仍是 10），几台仍要一起升，两端版本号不同时 doctor 和起会话报 `CCNM_E_VERSION`。配置不用改。

| 带了什么 | 记录 |
| --- | --- |
| P90 `ccnm ws add --allow-unattended-exec` | `docs/plan/ROADMAP.md` P90、[配置说明](../configuration.md) |
| P91 起会话前问项目机器开不开、命令让不让跑，不行就报 `CCNM_E_POLICY` 不起；每个新会话多建一次 SSH 连接（耗时见第 4 节） | ROADMAP P91、[排错手册](../troubleshooting.md#ccnm-项目-起不来报-its-runtime-would-refuse-it) |
| P92 `ccnm <项目> -c` 接着这个项目上一次的对话开（只支持 Claude） | ROADMAP P92、[研究记录](2026-10-15-p92-resume.md)、[使用说明](../usage.md#接着上一次的对话开--continue) |
| P93 rmcp 3.2.0 → 3.5.1：Claude Code 探测新协议、ccnm 起得慢时退回旧协议，会话里不再一个工具都没有 | ROADMAP P93、[研究记录](2026-10-15-p93-discover-fallback.md) |

## 4. 真机验证（零额度）

**P93**：夹具 [p93-discover-fallback.py](probes/p93-discover-fallback.py) 放到 fodelf 上，`--ssh xdwmbp` 经 ssh 起本机的 `mcp-serve`，和受管会话走同一条路。

| | 对照（直接 `initialize`） | 先探测再退回 | 退出码 |
| --- | --- | --- | --- |
| 换装前（本机 0.16.1） | 12 个工具 | `tools/list` 报 `request _meta is missing …` | 1 |
| 换装后（本机 0.17.0） | 12 个工具 | 12 个工具 | 0 |

**P92**：`ccnm run ccnm --detached -c`（本机发起）6.2 秒起好，报"接着 会话 036b54ef… 的对话"、新 id `4ebf5257…`。fodelf 上 Claude 的参数是 `--session-id 4ebf5257… --resume 036b54ef… --fork-session`；没人敲字，界面上显示着上次那段 `/context` 输出；这次 MCP 连接 2.5 秒连上、协商到新协议、没有取工具失败。看完 `ccnm stop ccnm`。没有发消息，没有调用模型。

**P91**：本机配置先备份，临时写回 `runtime_user = "bing"` 并加一个空目录的临时项目 `p91check`，验完按备份恢复（`cmp` 一致）：

- 只有这两处改动时，`ccnm run p91check --detached` 报 `CCNM_E_POLICY … not starting a session for `p91check`: its Runtime would refuse it`，第二行 `does not hold the Agent boundary`（会话那道门），末行指向 `ccnm doctor p91check`。
- 再给它加 `allow_unisolated_credentials = true`：退出码 33，第二行 `is not confined, so exec_command is refused`（命令那道门），理由是 `Not an admin`。
- 两次都没建会话：fodelf 的会话目录前后都是 53 个，tmux 里只有 xdo。

**每个新会话多出的那次 SSH 要多久**：P91 当时（10-15 下午）量的是 525–806 毫秒。今晚在 fodelf 上交替量 5 轮"空 ssh、ssh 跑 `ccnm --version`、ssh 跑 `runtime-audit`"：三者每轮几乎一样，前两轮 1.9–2.5 秒、后三轮 0.8–0.95 秒（Tailscale 这时走直连 IPv6，`tailscale ping` 23 毫秒）。审计本身在本机跑约 0.07 秒，共用账号和专用账号模式一样。所以多出来的就是建一次 ssh 连接，网络好时 0.5–1 秒，差时 2–3 秒。正常开会话（共用账号，含启动 Claude）两次 4.3、4.8 秒。拒绝那条路串了好几次 ssh，三次分别 26.9、10.6、7.5 秒；26.9 秒那次偏得多，原因没查清。

## 5. 没验的

- 真实模型下的 `-c`（模型怎么用上次的对话）没测。
- Claude 探测新协议的等待时限没量具体值，只知道在 1.38–3.07 秒之间；修好后超时退回也拿得到工具，这个值不再要紧。
- xdo 那个会话（10-13 起）换装时本机已经没有它的 `mcp-serve`，也就是工具通道早断了；它在 Claude 里 `/mcp` → `ccnm` → `Reconnect` 时起的就是 0.17.0 的 `mcp-serve`，这一步没验。
