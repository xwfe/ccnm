# 发版 v0.18.0，三台换装（2026-10-16）

用户 2026-10-16 在 P99 之后说"发个 0.17.1"，又说"几台机器都换上新版"。做法与 [v0.17.0](2026-10-15-release-0.17.0.md) 相同，这里只记不同的地方和结果。

## 1. 版本号

**0.18.0，次版本号**：用户说的是 0.17.1，按 0.17.0 那次的规则（加了命令或参数就升次版本号，补丁号只留给纯修 bug），这批加了 `ccnm add`、`ccnm rm` 两个新命令，问过用户后改发 0.18.0。内部协议号没变（`WIRE_LEVEL` 仍是 10，其他协议常量也都没动），几台仍要一起升，两端版本号不同时 doctor 和起会话报 `CCNM_E_VERSION`。配置不用改。

给人看的输出（起会话的提示、`ls`、`status`、`stop`、`result`、常见报错、`doctor` 结论）改了不少，拿它们写过脚本的要改；`ccnm rpc`、MCP 文本、错误码名、协议字段没动。

| 带了什么 | 记录 |
| --- | --- |
| P94 起会话的提示说人话：开关提醒每个两行加文档链接，会话摘要一行，连不上 Agent 时说下一步 | `docs/plan/ROADMAP.md` P94 |
| P95 `status`、`ls`、`stop`、`result` 和常见报错说人话；doctor 还不能用时点名先看哪行 | ROADMAP P95、[排错手册](../troubleshooting.md#doctor-的表怎么读) |

| P97 `ccnm add <项目目录>`，名字取目录名；`ccnm add` 就是 `ccnm ws add` | ROADMAP P97、[配置说明](../configuration.md#cli-改配置) |

## 3. 三台换装

同 v0.17.0：照运维手册"用发布包升级"，不留备份；本机用核对过的包，fodelf 自己从 GitHub 下载，hpsrv 由本机 scp 给 root 再 `install -o ccrun`、由它自己 `mv`。

**会话没停、只换文件**，和前几次一样。换装时 fodelf 上有四个受管会话（codingagent、keex、shun、xdo，tmux 都在），但本机一个 `ccnm internal` 进程都没有：shun 的 `mcp-serve`（pid 19277）下午记录基线时还在，写锁 10-17 00:12 已经交出，是它自己先断了，不是换装弄的。所以这次没有"旧代码攥着写锁"的问题。四个会话在 `ccnm ls` 里都是"工具断了"，在 Claude 里 `/mcp → ccnm → Reconnect` 时起的就是 0.18.0 的 `mcp-serve`。

| | 本机（Runtime / Operator） | fodelf（Agent） | hpsrv `ccrun` |
| --- | --- | --- | --- |
| 之前 | v0.17.0 `fc768740…` | 同左，Controller pid 51487 | v0.17.0 `bb0f0d77…` |
| 之后 | `ccnm 0.18.0`，`db87040f…` | 同左；`controller install` 后 pid 17800，报 `listening: ccnm 0.18.0`；四个 tmux 会话都还在 | `ccnm 0.18.0`，`fdbd285c…` |

doctor（本机发起）：`ccnm`、`codingagent`、`gld`、`keex`、`ragcheck`、`shun`、`xshun`、`xdo` 八个都是"可以用了（2 项不查）"、退出 0；Runtime、Agent、Controller、反向 SSH 都报 0.18.0。`xdo` 第一次是退出 20、`连 Agent 的 SSH` 报 `ssh fodelf: client_loop: send disconnect: Broken pipe`（那一阵两台之间网络慢，前面每个 doctor 跑了约 100 秒），3 秒后重跑就过了，`远端 MCP 握手` 拿到 12 个工具。

## 4. 换装后看过的

- `ccnm --help` 列出 `add` 和 `remove [alias: rm]`，`list` 那一行写着"目录在哪看 ccnm ws ls"；`ccnm ws --help` 的 `list` 写着"在不在跑看 ccnm ls"。
- `ccnm ls`：四个会话都是"运行中 · 没有终端接着、工具断了"，底下每个一行 `/mcp → ccnm → Reconnect`。

没有起新会话，没有调用模型；没有真的跑 `ccnm add` 或 `ccnm rm`（会改日用配置），这两条只在测试里用真实二进制跑过。

## 5. 没验的

- 四个开着的会话 Reconnect 之后接上 0.18.0 的 `mcp-serve`：等用户自己在 Claude 里重连。
- 真实模型下的任何一条。
- 三台临时文件：hpsrv 上 root 的 `/tmp/ccnm-0180.*` 和两个包、fodelf 的下载目录已删；本机的包留在会话临时目录里。
