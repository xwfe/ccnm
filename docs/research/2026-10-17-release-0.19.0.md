# 发版 v0.19.0，三台换装与真机验证（2026-10-17）

用户 2026-10-17 在 P100–P104 之后说"合并清理分支和 worktree，最后发版并在三台机器上换装、做真机验证"。发版与换装做法同 [v0.18.0](2026-10-16-release-0.18.0.md)，这里只记不同的地方和结果。

## 1. 版本号

**0.19.0，次版本号**：用户没指定版本号。按 0.17.0 起的规则（补丁号只留给纯修 bug），这批有新行为（P100 进会话时替人重连、P102 长对话交接）和新能力（P104 `search_text` 收文件），所以升次版本号。没有新命令和参数；内部协议号没变（`WIRE_LEVEL` 仍是 10，`StartReport.tools`、`LiveSession.compactions` 是可省的新字段），几台仍要一起升，两端版本号不同时 doctor 和起会话报 `CCNM_E_VERSION`。配置不用改。

`ccnm <项目>` 的退出码多了一种情况：会话在跑、工具断了又接不上时不 attach，用失败本身的退出码（连不上项目机器 21、版本不同 11、项目机器不肯 33、其余 3）。`ccnm.workspace-mcp/1` 两处冻结之后的变化见协议文档开头：`read_output` 的缺陷修复（结果里的 `offset` 可能比请求的大 1–3）、`search_text` 的 `path` 收文件（加法），以及顺带堵上的 `.git` 缺口（`path` 落进 `.git` 时报 `CCNM_E_POLICY`）。

## 4. 真机验证（零额度，没调模型）

**doctor**（本机发起）：`ccnm`、`gld`、`keex`、`ragcheck`、`xshun`、`xdo` 六个"可以用了（2 项不查）"，Runtime、Agent、Controller、反向 SSH 都报 0.19.0。`codingagent`、`shun` 各 1 项失败，是 `远端 MCP 握手` 报 `write guard is busy; another session still owns this working tree`——这两个项目正开着用户的会话、工具通着，`mcp-serve` 攥着写锁，探测握手进不去，是预期的。

**P103、P104 在 Linux 上**：把 `v0.19.0` 的 `tests docs/protocol docs/plan scripts clients` 用 `git archive` 打包传到 hpsrv，以 `ccrun` 身份用装好的发布二进制跑中立 MCP 客户端测试（`CCNM_BIN=~/.local/bin/ccnm python3 -m unittest tests.test_remote_workspace_mcp`）：53 条全过，含 `test_read_output_from_inside_a_character_and_past_a_bad_byte`、`test_search_text_searches_one_named_file`。跑完删了目录。

**P100–P102**：在没开会话的 `ccnm` 项目上起测试会话（本机 `ccnm run ccnm --detached`），断工具用 fodelf 上一个小脚本：在 N 秒内把这个会话 Claude 名下的传输进程（`internal agent-transport` / `internal mcp-serve`）一出现就 TERM 掉，别的会话不碰。界面与进程在 fodelf 上看（`tmux -L ccnm capture-pane`、`ps`）。Claude Code 是 fodelf 上的 2.1.302。

| 验什么 | 怎么做 | 结果 |
| --- | --- | --- |

测试会话都已 `ccnm stop`。

**验证中发现**：全新会话（一句话没说过）的输入框里是暗色的占位提示 `❯ Try "write a test for <filepath>"`，`capture-pane -p` 的纯文本里和草稿一样，所以这种会话工具断了时 ccnm 不敲、让人自己敲。`/clear` 之后输入框是空的、没有提示，不受影响。修法见第 5 节。

**没验的**：真实模型写交接（`Stop` 收到真回复）、压缩计数和压缩后模型怎么建议（`/compact` 要调模型）；用户自己那四个会话里的重连（keex、xdo 工具断着，等用户下次 `ccnm keex` 时 P100 会替人接）。

## 5. 补发 v0.19.1

**0.19.1，补丁号**：只修第 4 节验证中发现的那一处，没有新行为。`ccnm` 读 Claude Code 界面改用 `capture-pane -e`（带颜色码）：`❯` 后面只有暗色字就是空输入框，正常粗细的字才是草稿（`e246464`，样本是 fodelf 上抓的两张真实带色截屏 `tests/fixtures/claude-tui-2.1.302/`，状态栏里的额度用量已去掉；只看纯文本的旧判断下新测试是红的）。内部协议号不变，几台仍要一起升。
