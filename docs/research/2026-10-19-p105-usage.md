# P105：`ccnm usage` 查订阅额度（2026-10-19）

## 1. 由来

用户要一个查"用量余量"的功能。ccnm 管的 Claude Code / Codex 都是订阅登录，额度（Claude 的 5 小时窗口和每周额度、Codex 的 5 小时 / 7 天窗口）跟着 **Agent 那台的登录**走：同一个登录下所有项目共用一份。所以命令按登录问，不按项目问。

## 2. 用哪个入口

前提来自 [AGENTS.md](../../AGENTS.md)：不读认证文件内容、不复制凭据、不实现私有模型客户端，官方 CLI 的参数和输出以实测为准。

| 入口 | 用不用 | 原因 |
| --- | --- | --- |
| `claude --print /usage --output-format json` | **用** | 官方 CLI 自己的本地命令，凭据它自己读；实测不发模型请求（第 3 节） |
| `codex app-server` 的 `account/rateLimits/read` | **用** | 官方协议里的方法，`app-server generate-json-schema` 给得出结构；凭据 Codex 自己读 |
| `GET https://api.anthropic.com/api/oauth/usage` | 不用 | Claude Code 的 `/usage` 背后就是它，但直接调要拿 OAuth token，等于读凭据 |
| 状态栏输入里的 `rate_limits`、`--output-format stream-json` 的 `rate_limit_event` | 不用 | 只在会话发过模型请求之后才有，问一次就要花额度 |

## 3. 实测

全部零模型请求。命令和临时目录都在会话 scratchpad 或 fodelf 的 `/tmp` 里，测完删掉。

### 3.1 Claude：`/usage` 不调模型（本机，2.1.300，假服务端）

`env -i HOME=<空目录> PATH=… ANTHROPIC_BASE_URL=http://127.0.0.1:<端口> ANTHROPIC_API_KEY=<假值> claude -p /usage --output-format json --no-session-persistence --strict-mcp-config`，假服务端记下所有请求：

- 只收到 `HEAD /api/hello`（连通性检查），没有 `/v1/messages`。
- 结果文档：`"local_command": "usage"`、`"num_turns": 0`、`"duration_api_ms": 0`、`"total_cost_usd": 0`，`duration_ms` 57。
- `result` 只有本次会话的费用 5 行（`Total cost:`、`Total duration (API):`、`Total duration (wall):`、`Total code changes:`、`Usage:`），全是 0。API key 登录没有订阅额度可报。
- 去掉 `--setting-sources ""` 与否结果一样。

存为 [claude-usage-api-key-2.1.300.json](../../tests/fixtures/usage/claude-usage-api-key-2.1.300.json)。

### 3.2 Claude：订阅登录（fodelf，2.1.280 和 2.1.303）

macOS 上 Claude 的登录在钥匙串里，ssh 会话读不到（3.3），所以借 ccnm 自己那个 tmux server（`tmux -L ccnm`，由 Controller 在登录会话里起的）临时开一个会话跑。加了一个 `BUN_OPTIONS=--preload` 脚本：记下 `fetch` 的每个 URL，遇到 `/v1/messages` 直接抛错——保证就算判断错了也不会花额度。

- fodelf 上两个 `claude`：`/opt/homebrew/bin/claude` 是 **2.1.280**，`~/.local/bin/claude` 是 **2.1.303**。Controller 按 ccnm 的查找顺序用后者（launchd 的 PATH 里没有 `~/.local/bin`，再找 `~/.local/bin/claude`）。两个都测了，输出一致。
- `fetch` 只有 `POST /api/eval/sdk-…`（功能开关）和 `POST /api/event_logging/v2/batch`（遥测），没有 `/v1/messages`。额度数据不是经 `fetch` 取的（Claude Code 有别的 HTTP 客户端），preload 看不到，这不影响结论：模型请求走 `fetch`，而它一条都没有。
- 结果文档同样是 `local_command: "usage"`、`num_turns: 0`、`duration_api_ms: 0`；`duration_ms` 935 / 960，整条命令墙钟 3.4–3.8 秒。
- `result` 开头：

  ```text
  You are currently using your subscription to power your Claude Code usage

  Current session: 17% used · resets Oct 19 at 6pm (Asia/Singapore)
  Current week (all models): 38% used · resets Oct 24 at 11am (Asia/Singapore)
  Current week (Fable): 36% used · resets Oct 24 at 11am (Asia/Singapore)
  ```

  后面是 `What's contributing to your limits usage?`：按本机对话记录估算的"是什么在花额度"，带 skill 和 MCP server 名字。ccnm 不带回这一段。
- 重置时间是 Claude 自己按 Agent 那台的时区写的原话。同一个窗口，早几分钟那次写的是 `5:59pm`，这次写的是 `6pm`：怎么取整是 Claude 的事，ccnm 照抄、不换算。
- `Current session` 就是 5 小时窗口：Claude Code 包里把 `five_hour` 映射成 `session`，状态栏文档也写 `five_hour` 是 "5-hour session limit"。
- `--no-session-persistence` 下不留对话记录，但每个工作目录会在 `~/.claude/projects/<目录>/` 下留一个空的 `memory/`。所以 ccnm 固定在 `<状态目录>/usage` 里跑，最多只留这一个。测试留下的三个空目录已经用 `rmdir` 删掉。

存为 [claude-usage-subscription-2.1.280.json](../../tests/fixtures/usage/claude-usage-subscription-2.1.280.json)、[claude-usage-subscription-2.1.303.json](../../tests/fixtures/usage/claude-usage-subscription-2.1.303.json)。脱敏：`session_id`、`uuid` 换成全零 UUID，估算段里一个私人 skill 名换成 `/example-skill`。

### 3.3 Claude：没登录时（fodelf，ssh 会话，2.1.303）

ssh 会话里 `security show-keychain-info` 报 `User interaction is not allowed`，`claude auth status` 回 `loggedIn: false`。这时 `claude -p /usage` 的结果和 API key 一模一样：`local_command: "usage"`、只有费用 5 行、退出码 0。

所以只看 `/usage` 分不清"没登录"和"没有订阅额度"。ccnm 先跑一遍 doctor 也在用的 `claude auth status`，没登录直接报 `CCNM_E_AUTH`，登录了才跑 `/usage`。

### 3.4 Codex：`account/rateLimits/read`

- **结构**：0.154.0（ccnm 钉的版本，下载到 scratchpad 单独目录）和本机 Homebrew 的 0.162.1 各自 `app-server generate-json-schema`，`GetAccountRateLimitsResponse` 的字段一样：顶层 `rateLimits`（必有）、`rateLimitsByLimitId`、`rateLimitResetCredits`、`rateLimitUpsell`、`accountId`、`ordinaryUsageAllowed`；窗口 `RateLimitWindow` 是 `usedPercent`（必有）、`windowDurationMins`、`resetsAt`（Unix 秒）。
- **真实回复**：0.162.1 用本机日常的 ChatGPT 登录（`~/.codex`，没用 0.154.0 去碰它，免得旧版本动新版本的状态库）发 `initialize` → `initialized` → `account/rateLimits/read`，回复里 `planType: "prolite"`，`primary` 是 7 天窗口（`windowDurationMins: 10080`）已用 100%，`rateLimitReachedType: "rate_limit_reached"`，`rateLimitResetCredits.availableCount: 3`，`secondary: null`。存为 [codex-rate-limits-0.162.1.json](../../tests/fixtures/usage/codex-rate-limits-0.162.1.json)，`accountId` 和重置券 id 换成占位值。
- **stdin 关早了回复会丢**：三条请求一次写完就关 stdin，只收到 `initialize` 的回复和两条通知，0.5 秒后进程退出，额度那条没有。所以 `process::stream_lines` 加了"写完 stdin 先不关，回调说 `Flow::Close` 再关"，见 `crates/ccnm-core/src/process.rs`。

## 4. 实现

- `crates/ccnm-core/src/quota.rs`：额度的数据结构和给人看的渲染。Codex 的重置时刻按敲命令那台的时区显示（和 `ccnm log` 一样），Claude 的照抄它自己的原话。
- `crates/ccnm-core/src/provider/claude/usage.rs`：命令行、2.1.280 这条版本线、结果解析。结果不是本地命令的（`local_command` 不是 `usage`）就拒绝，不把模型的回答当额度。
- `crates/ccnm-core/src/provider/codex/usage.rs`：起 `codex app-server`（剥掉认证环境变量、`CODEX_HOME` 指实例目录），只认 0.154.0（和会话同一条线）。
- `AgentProvider::quota_at`：先版本和登录，再问额度。Controller 新增 `usage` 请求（和 `claude-auth` 共用实例 / 配置目录校验），Agent 侧 `internal agent-usage` 先确认 Controller 在登录会话里，Runtime 侧不带项目名时按"Agent 别名 + 实例 + legacy 配置目录"去重。
- 对端太旧的两种情况：Agent 上的 ccnm 不认 `agent-usage`（"too old for `ccnm usage`; install the same version on both machines"）；文件换了新的、Controller 进程还是旧的（"restart it so it runs the installed one: launchctl kickstart -k …"）。

## 5. 真机端到端（fodelf，没换已装的 ccnm）

- **对端是旧版本**：本机新编的 ccnm 用日常配置跑 `ccnm usage`，fodelf 装的是 0.19.1：输出 `fodelf（8 个项目共用）` 下一行 `CCNM_E_VERSION: the ccnm on fodelf is too old for \`ccnm usage\`…`，退出码 11，0.39 秒。8 个 legacy 项目按登录去重成一次 ssh。
- **新版本 + 临时 Controller**：把新二进制拷到 fodelf 的 `/tmp/ccnm-p105/`，用单独的 `XDG_STATE_HOME` 在 `tmux -L ccnm` 里起一个临时 Controller（不碰已装的 ccnm、LaunchAgent 和三个在跑的会话），本机用临时配置（`ccnm_bin` 指向一个导出 `XDG_STATE_HOME` 的包装脚本）跑：
  - `ccnm usage`：ssh → `internal agent-usage` → 临时 Controller。Controller 的 `managername` 是 `Background`（tmux 里起的都是），按现有规则**不算登录会话**，`CCNM_E_NOT_READY: not asked: the controller is not in a login session…`，退出码 3。这是对的：doctor 和起会话用的是同一条规则，真正的 Controller 是 LaunchAgent，报 `Aqua`。
  - 直接往临时 Controller 的 socket 发 `{"protocol":1,"body":{"request":"usage"}}`：3.56 秒回 `reply: usage`，`version 2.1.303`、`plan max`、三个窗口（当前 5 小时 1%——18:00 刚重置过——本周 38%、Fable 36%）和那句账号说明；`<状态目录>/usage` 建成 0700。
  - 测完停掉临时 Controller、删 `/tmp/ccnm-p105`、`rmdir` 掉 Claude 为这个目录建的空 `memory/`；fodelf 的 tmux 会话只剩原来的 `ccnm-keex`、`ccnm-shun`、`ccnm-xdo`。

## 6. 没验的

- **真正的 LaunchAgent Controller 回 `usage`**：当时要换装才能验，没做，拆成上面两段验。**同日 v0.20.0 换装后已真机走通**，见[发版记录](2026-10-19-release-0.20.0.md)。
- **Codex 经 ccnm 实例**：0.154.0 + 实例目录里的真实登录没调过；结构靠 0.154.0 自己生成的 schema 和 0.162.1 的真实回复，`ask()` 的管道交互由一个行为照真实服务端写的假 `codex` 脚本测（`provider/codex/usage.rs`）。
- **Linux Agent**、legacy 写了 `claude_config_dir` 的、`--agent` 换实例、在 Agent 那台上敲 `ccnm usage`：都只有离线测试。
- **Claude 2.1.280 以前的版本**：没测，ccnm 也不问（见 `MIN_VERSION` 的注释）。
- **订阅之外的输出**：Claude 的 `Spend limit:`（网关设了花费上限时）、Codex 的多组 limit 和 credits，只按 schema / Claude Code 包里的文字写了解析和渲染，没有真实样本。
