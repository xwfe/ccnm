# 发版 v0.20.0，三台换装与 `ccnm usage` 真机复验（2026-10-19）

用户 2026-10-19 在 P105 之后说"发版、三台换装，然后在本机真机跑 ccnm usage 复验"。发版与换装做法同 [v0.19.0](2026-10-17-release-0.19.0.md)，这里只记不同的地方和结果。

## 1. 版本号

**0.20.0，次版本号**：用户没指定版本号。按 0.17.0 起的规则（加命令、加参数升次版本号，补丁号只留给纯修 bug），这次新增了 `ccnm usage`。配置不用改。

几台仍要一起升：新增的内部命令 `internal agent-usage` 和 Controller 的 `usage` 请求只有新版本认得。内部协议号没变（`WIRE_LEVEL` 仍是 10）——旧对端在已有的命令上照常工作，只是不认这两个新东西，`ccnm usage` 碰到时各说一句该怎么办（[排错手册](../troubleshooting.md#ccnm-usage-查不到额度)）。**AI 那台换完文件要重启 Controller**（`ccnm controller install`，和以前每次一样）：不重启，跑着的还是旧进程，`ccnm usage` 报 `the controller here was started by an older ccnm`。

| 带了什么 | 记录 |
| --- | --- |
| P105 `ccnm usage [项目] [--agent 实例]`：每个 AI 登录问一次，列出各个额度窗口已用、剩余、重置时间；Claude 用 `claude --print /usage`、Codex 用 app-server 的 `account/rateLimits/read`，不读凭据、不发模型请求 | ROADMAP P105、[研究记录](2026-10-19-p105-usage.md)、[使用说明](../usage.md#查额度还剩多少ccnm-usage) |

## 3. 三台换装

同 v0.19.0：本机用核对过的包；fodelf 自己从 GitHub 下载、核 sha256、`controller install`；hpsrv 由本机 scp 给 root、`install -o ccrun`、由它自己 `mv`。**会话没停、只换文件**：fodelf 上开着用户的三个会话（keex、shun、xdo），换装前后 tmux 都在；本机没有 `mcp-serve`（三个会话的工具之前就断着），没有旧代码攥写锁的问题。

## 4. 真机验证（零额度，没调模型）

**`ccnm usage`**，fodelf 上 Claude Code 2.1.303（`~/.local/bin/claude`），订阅 `max`：

| 在哪敲 | 命令 | 结果 |
| --- | --- | --- |
| 本机 | `ccnm usage` | 一块：`fodelf（8 个项目共用） · Claude Code 2.1.303 · max`，当前 5 小时已用 5%、本周（全部模型）39%、本周（Fable）37%，各带 Claude 原话的重置时间，外加那句账号说明；4.19 秒，退出 0。8 个 legacy 项目去重成一次 ssh |
| 本机 | `ccnm usage ccnm` | 同上，标题是 `fodelf · …`（单个项目不写共用数），退出 0 |
| 本机 | `ccnm --lang en usage` | `fodelf (shared by 8 projects) · …`，三行用 Claude 自己的标签（`Current session` 等），退出 0 |
| 本机 | `ccnm usage ccnm --agent claude-main` | `CCNM_E_CONFIG: --agent requires an instance-selected workspace…`，退出 10（legacy 项目没有实例可换，和别的命令一样） |
| 本机 | `ccnm usage --agent x` | `CCNM_E_INVALID_ARGS: … name the workspace too`，退出 34 |
| fodelf | `ccnm usage` | `本机 · Claude Code 2.1.303 · max`，同样三个窗口，2.95 秒，退出 0（这台没登记实例，只问默认 Claude） |
| fodelf | `ccnm usage keex` | 先经 ssh 问本机 keex 用哪个登录，再问 Controller，结果同上，退出 0 |

数是 Claude Code 的 `claude --print /usage` 自己报的，格式和 [P105 研究记录](2026-10-19-p105-usage.md)第 3.2 节的原文一致；没有在交互界面里同时敲 `/usage` 逐数对照。5 小时窗口那天 18:00 刚重置过，所以是 5%。问完 fodelf 上 `~/.local/state/ccnm/usage` 是 0700，`~/.claude/projects/` 下只多了 `-Users-fodelf--local-state-ccnm-usage/memory/` 一个空目录，没有对话记录。

**doctor**（本机发起）：`ccnm`、`codingagent`、`gld`、`keex`、`ragcheck`、`shun`、`xshun`、`xdo` 八个都是"可以用了（2 项不查）"、退出 0；Runtime、Agent、Controller、反向 SSH 都报 0.20.0。

**文档顺带改的**：使用说明里的示例换成上面这次的原样输出——标题里 `）` 和 `·` 之间实际有一个空格，之前手写的示例漏了。

## 5. 没验的

- **Linux 当 Agent**、legacy 写了 `claude_config_dir` 的项目：没有这样的日用配置。
- hpsrv `ccrun` 只换了文件、核了版本，日用项目都不走它，这次没有经它的会话或 doctor。
