# P114：`--on` 选机器和实例，一个项目能在任何一台登记过的 AI 机器上跑（2026-10-28）

用户 2026-10-28 要：已经登记的项目不改名字、不改目录，`ccnm <项目> --on b` 就换到另一台 AI 机器接着干（场景是一台额度用完）；机器和实例都用 `--on`。怎么用写在[使用说明](../usage.md#换一台-ai-机器--on)，这里记改了什么、为什么这么定、验到哪一步。

## 1. 改了什么

**解析**（`crates/ccnm-core/src/on.rs`，新模块）：`--on` 写 `机器`、`机器/实例` 或 `实例`。机器认 `[nodes.*]` 的名字，也认 ssh 别名（恰好一台用这个别名时）；只写一个名字时先当机器、不是机器再当项目默认那台上的实例。`agent_node` 写法的项目没有实例可选，一个不是机器的名字直接报 `no machine called …` 并列出能选的机器。写项目机器自己、写没有 ssh 别名的节点、别名两台共用，各报各的错。

**挪项目**：项目机器上的命令先算出这次去哪台（`Config::place`：`--on` > 记下的上次 > 项目默认），再克隆一份配置、把这个项目的 Agent 节点换掉（`moved_to`，换完重新校验）。之后整条 launcher 路径读的都是这份配置，不知道 `--on` 存在——所以 `run`、`attach`、`status`、`stop`、`result`、`doctor`、`usage`、`mcp probe` 一次都接上了，没有逐个改 ssh 逻辑。

**记住上次去了哪台**：会话起成功后，项目机器写 `~/.local/state/ccnm/workspaces/<项目>/on`（一行节点名，先写临时文件再改名）；回到默认那台时删掉。不带 `--on` 的命令去记下的那台。再起会话时先问那台：会话还在就接回，已经结束就回默认那台并删记录，问不到就打一行说明、回默认那台。`ccnm ls`、不带项目名的 `ccnm status` 按记下的机器去问；`ccnm log` 把默认那台和记下的那台都问一遍、按别名去重。记录里的机器后来从配置里删了，就当没有记录。

**一个项目一个写入者**（P114.3）：`--on b` 而项目还在别台有会话时，在终端里问 `[y/N]`，答 `y` 才 `stop` 那边再起；不在终端里报 `CCNM_E_POLICY` 并给两条命令。用 `CCNM_E_POLICY` 是和写锁被占时的报法一致（没有专门的 busy 码）。问不到那台照样起：写锁本来就挡第二个写入者。`--print` 不移动项目，也不做这一步。

**项目机器认哪些 AI 机器**（`instance.rs` 的 `bind_workspace`）：实例写法的项目，原来只认配置里写的那一台；现在认项目默认那台，或配置里任何一台带 ssh 别名、又不是项目机器自己的。节点名是 Agent 自己报的，能以执行账号 ssh 进来的人报什么都行，所以这一条从来不是安全边界，防的是"会话走错了 Runtime"。`agent_node` 写法的项目，项目机器本来就不核对来的是哪台，`--on` 只要项目机器这一边是新版本就能用，AI 机器那边的 ccnm 不用换。

**改默认机器、加机器**：`ccnm ws add <已有项目> --on <机器>`（不带目录和别的选项）只改 `agent_node` 或实例写法的 `agent.node`，其余一个字节不动——原来没给目录时会取当前目录，可能把项目改指到别处。`ccnm init --agent <另一个别名>` 在已经有一台时改成**加一台**，节点名取别名（非字母数字换成 `-`）；原来这么跑会把 `nodes.agent.ssh` 换掉，所有项目一起换了机器。

**额度**：不带参数的 `ccnm usage` 问完项目在用的登录以后，再把登记过、没被问到的机器各问一次默认登录（`launcher::machine_usage`）；`ccnm usage --on <机器>` 只问那一台。

**旧名字**：`--agent`、`ws add --agent-node` 是 clap 的别名，照旧能用，多打一行"已改名为 --on"（扫命令行时跳过 `init`，那里的 `--agent` 是另一回事）。程序里给人看的提示（status 的"加 --on codex-main 看它"、`ws add` 有好几台时）都改成 `--on`。Machine API（`ccnm.machine/1`）和所有内部 wire 都没动。

AI 机器上敲的命令：那台不存项目列表，`--on` 只能是它自己的实例或它自己（`on::local_instance`），写别的机器报错、让人去项目机器上敲。

## 2. 离线验证

本机 macOS arm64：

- 先红：`crates/ccnm-cli/tests/on.rs` 7 条和 `instance_config::another_registered_ai_machine_binds_the_same_project`，把产品源码 stash 掉、对旧代码跑，**8/8 红**（7 条 CLI 是参数不认识或行为不对，绑定那条是 `Agent identity node does not match the Runtime workspace reference`），恢复后全绿。
- `on.rs` 单元测试 12 条：三种写法、ssh 别名、机器名优先于同名实例、项目机器自己、没别名的节点、别名两台共用、`agent_node` 项目写错名字列出机器、挪项目只改机器、记录的写入/覆盖/删除、记录里的机器已不在配置、AI 机器上只能选自己的实例。
- CLI 集成 7 条用假 `ssh`（记下拨了哪个别名，按测试说的回 `agent-status`）：按节点名和别名都拨到 `hpsrv.invalid`、不带 `--on` 拨默认那台；旧 `--agent` 能用且提示改名；不认识的机器不拨任何一台；默认那台有会话时脚本里 `--on` 被拒、只问不起、不写记录；有记录时 `stop` 去记下的那台，起会话时先问它、问不到回默认那台并删记录；`ws add --on` 只改那一行；`init` 再跑一次另一个别名是加一台、再跑一次说"已经是这么写的了"。
- 两条旧测试的断言按新提示改了（`cli.rs` 里有好几台时提示 `--on <machine>`，`session_identity.rs` 里实例提示 `--on codex-main`），不是放宽。
- 门禁：见第 4 节。
