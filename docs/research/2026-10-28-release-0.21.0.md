### 5.1 查出来的：`cmd` 里写 `bash`，进的是 WSL

两个模型都先用 `cmd` 写了 `bash …`。`cmd` 不经 shell，程序按 PATH 找；这台机器装了 WSL，排第一的 `bash` 是 `C:\Windows\System32\bash.exe`，它是 WSL 的启动器，跑起来的是 Linux 发行版（这台是 kali）。ccnm 的 `shell` 一直避开它，只用 Git for Windows 的 bash（`platform.rs` 的 `git_bash`）；可 `cmd` 里点名的程序，ccnm 原样去起。

- **Claude** 先跑 `where bash`，看出问题，改用 Git 的 `bash.exe` 全路径，一次就过了。
- **Codex** 直接跑了 `["bash","build.sh"]`：进了 WSL，22 秒后退出 1。这期间，WSL 里的 mise 从项目目录往上找，找到了 Windows 账号自己的 `C:\Users\<账号>\.config\mise\config.toml`（在 WSL 里路径是 `/mnt/c/…`），把里面列着、但 WSL 里还没装的工具装上：java corretto-8 装好了（212 MB），npm:whistle 装好了（21 MB），maven 下载报 404，没装上。随后 Codex 用 `where.exe` 查出原因，改用 `D:\scoop\shims\bash.exe`（scoop 给 Git Bash 做的 shim）跑过了。
- **留下的东西**：WSL 里多了上面那几个目录。WSL 自己的 `~/.config/mise/config.toml` 和 Windows 那份 `config.toml`，修改时间都变成了那次运行中的 16:47:46（测试机时间）。两份现在都只是工具清单，内容改没改不知道，因为没有之前的副本。我没动这两份配置；装上的目录在清理时删了（第 6 节）。WSL 里的进程跑在 WSL 的虚拟机里，不在 ccnm 给命令建的 Job 里；这次命令自己结束了，WSL 随后也自己停了。如果命令卡住、被 ccnm 停掉，Linux 那边的进程会不会一起结束，这次没测。
