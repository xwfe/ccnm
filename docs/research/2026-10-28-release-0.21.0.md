## 3. Windows Runtime 真机验收：零额度那一半（P112.1、P112.3）

测试机同 P111（Win11 中文系统，sshd 默认 shell 是 Windows PowerShell，账号在 Administrators、钥匙登录是 High）。用户同意上测试机、测完清理。Windows 上装的是 CI 运行 40629922433 打的包（提交 cc2c938，和 v0.21.0 只差版本号与两处 Windows 测试/超时），照安装文档放进 `%USERPROFILE%\.local\bin`；项目是探针 `prepare` 生成的一棵树（README、src、notebook、一像素 PNG、一个 skill、一个 node 写的 MCP server 和 `.mcp.json`），在 `%TEMP%\ccnm-p112\proj`，`git init` 过，workspace 写了 `external_mcp = "coding"`。这台 macOS 用同一提交的构建、临时 `--config`（`[nodes.runtime] ssh = "win11"` + 全路径 `ccnm_bin`）跑 `ccnm mcp bridge proj --mode coding`。

**tailnet**：开始时测试机的 Tailscale 卡在"Tailscale is starting / unexpected state: NoState"，这边看它离线两天。`Restart-Service Tailscale` 后一两分钟恢复，`ssh win11` 走 tailnet 照常（bridge 只用 `/usr/bin/ssh` 和 `~/.ssh/config` 里的别名，局域网绕不过去）。

### 3.1 中立客户端经 bridge 调全部工具

探针 [p112-windows-bridge.py](probes/p112-windows-bridge.py) `run`（客户端是仓库里的 `tests/mcp_client.py`，不 import ccnm）。**19 项全过**：`tools/list` 正好 12 个；`workspace_info` 报 `windows/x86_64`；`read_file`、`list_files`、`search_text`、`view_image`、`read_notebook`、`load_skill` 结果对；`apply_patch` 一次加一个 CRLF 文件、按版本整篇改写另一个；`exec_command` 的 `cmd`（`git status --porcelain`）和 `shell`（Git Bash 里 `cat`）；`call_mcp_tool` 经 `node` 的 `.cmd` shim 转接项目的 server；后台命令起、`read_output` 读到 `tick-1…3`、`stop_command` 停；像 Host 按 Esc 那样发 `notifications/cancelled`，cmd 下的 `ping` 和 Git Bash 下的 `sleep` 约 1 秒内都没了；会话关掉 5 秒后两次查询里都没有这次起的进程；马上再开一个 coding 会话写得进去（写锁交出了）。

前两次没全过都是探针的错：WMI 报的映像名是大写的 `PING.EXE`；查询自己那次 ssh 会话的 conhost 被当成残留（PowerShell 的 `ParentProcessId` 是 UInt32，按 `[int]` 查哈希表永远不中）；`search_text` 的参数是 `query`。

### 3.3 断网、停止、防睡眠

| 场景 | 做法 | 结果 |
| --- | --- | --- |
| 断 30 秒再恢复 | `ping -n 45` 跑着时把 bridge 那条 ssh `SIGSTOP` 30 秒再 `SIGCONT`（两边都不收不发；没改防火墙） | 命令照常回来，会话接着能用；关掉后无残留、写锁 `released` |
| 连接被掐断 | 后台 `sleep 600` 跑着时 `SIGKILL` 那条 ssh | **5 秒内** Windows 上 `ccnm.exe`、`bash.exe`、`sleep.exe` 全没了，写锁 `released`，新会话立刻写得进去。sshd 自己不收客户端没了的会话（#1751），是 mcp-serve 读到 stdin 结束退出、Job 带走命令树 |
| Esc | 见 3.1 | 约 1 秒 |
| 防睡眠 | 会话开着时、关掉 4 秒后各看一次 `powercfg /requests` | 开着时 SYSTEM 一栏有 `…\.local\bin\ccnm.exe`，关掉后没了 |

**没验到的**：网络悄悄没了、TCP 也不断开（要改防火墙，没做）——那时 Windows 这边要等 TCP 保活才发现，mcp-serve 可能一直占着写锁；"空闲 10 分钟不睡"单独归给 ccnm（这台机器上 GameViewer、一个 `[DRIVER] Legacy Kernel Caller` 请求、测试用的防睡眠进程都在撑着，分不开）。那条 Legacy Kernel Caller 在没有任何 ccnm 进程时也时有时无，不是 ccnm 的。

### 3.4 CI 上的慢

`windows_doctor` 的清理用例在 runner 上量到 30.1（超时）、19.7、30.1（超时）、25.6 秒，测试机上 sshd 下 0.3 秒。先后怀疑过"没导入 CimCmdlets"和"测试环境太简陋"，改了都还慢，两个解释都不成立。c050d40 把这一步的上限从 30 秒放到 90 秒，并让测试另量一个只启动就退出的 PowerShell：运行 40639057492 里它 0.29 秒，同一次清理预览 31.7 秒（90 秒上限内，用例过了）。所以慢的是 runner 上那次 WMI 查询（`Get-CimInstance Win32_Process`），不是 PowerShell 启动；为什么慢没查。
