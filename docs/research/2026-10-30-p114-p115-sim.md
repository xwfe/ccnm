# P114.4、P115.5：用模拟的第二台 AI 机器验换机器和带交接（2026-10-30，零额度）

P114.4 和 P115.5 的真机部分要两台 AI 机器。手头能当 AI 机器的只有一台，Linux 测试机上没有 AI 服务，用户 2026-10-30 定"简单模拟即可"。这里记模拟怎么搭、验到了什么、顺带查出的缺陷，以及模拟替代不了的部分。离线部分见 [P114 记录](2026-10-28-p114-on.md)和 [P115 记录](2026-10-28-p115-carry.md)。

## 1. 怎么模拟

第二台 AI 机器，用同一台物理 AI 机器（macOS arm64，Claude Code 2.1.312）上的**两份并存部署 a、b** 来扮。项目机器还是本机。日用的配置、数据目录、Controller、`~/.claude` 一律不改，用到的东西都是新建的，测完整个删掉。

| 在哪 | 放了什么 | 为什么要它 |
| --- | --- | --- |
| 项目机器 `~/p114sim/` | 临时 Runtime 配置：一个测试项目 `sim`，默认在 a；`[nodes.a]`、`[nodes.b]` 用同一个 ssh 别名，`ccnm_bin` 各指向 AI 机器上自己那份的包装脚本，`claude_config_dir` 各指向自己的 Claude 配置目录。包装脚本导出 `CCNM_CONFIG`、`XDG_STATE_HOME` | 不碰日用项目列表和写锁 |
| AI 机器 `~/p114sim/a/`、`~/p114sim/b/` | 各自的配置（`this = "a"` / `"b"`，`[nodes.runtime] ccnm_bin` 指项目机器上的包装脚本）、数据目录、`TMUX_TMPDIR`、包装脚本；Controller 用自己的 Label（`dev.ccnm.p114sim.a` / `.b`），plist 不放进 `~/Library/LaunchAgents`，用 `launchctl bootstrap gui/<uid>` 加载 | ccnm 固定用 `tmux -L ccnm`，不分 `TMUX_TMPDIR` 就会进日用的 tmux server；日用 Controller 占着标准 Label |
| AI 机器 `~/p114sim/{a,b}/claude/` | `settings.json` 的 `env` 把 `ANTHROPIC_BASE_URL` 指到本机 127.0.0.1 上的假模型（a 用 18761，b 用 18762），配一个假的 `ANTHROPIC_API_KEY`；`.claude.json` 预先认可这个 key、跳过首启引导 | 不花额度；这个目录里没有登录，就算没接到假模型也只会 401 |
| AI 机器 `~/p114sim/model/` | 假模型：按人最后打的那句话里的暗号回。`P114TOOL` 先调 `apply_patch` 写 `sim-<机器>.txt`、再调 `exec_command` 看 `pwd`；`P115WRITE` 回一段带单独一行 `[ccnm handoff]` 的交接；其他回一句普通的话。每条请求原样存盘 | 能看到真正发给模型的第一条请求 |

两台用同一个 ssh 别名不影响判断：`--on` 认的是节点名，"换没换机器"比的也是节点名（`carry_over` 里的 `previous.node == target.node`）。代价是提示里两台都叫同一个别名，比如"带上了 <别名> 上一次会话的交接"。真机上这里会是两个名字。

## 2. 顺带查出的缺陷：旧写法的 `claude_config_dir` 起会话时被丢掉

第一次在 a 上起会话，Claude 弹出了"信任这个文件夹吗"，底栏显示的是真实账号的额度。看 Claude 进程的环境，**没有 `CLAUDE_CONFIG_DIR`**，用的是日用的 `~/.claude`；可是同一份配置下，`ccnm doctor` 报的是 `logged in via api_key`，查的是 `claude_config_dir` 那个目录。会话记录 `session.json` 里的 `claude_config_dir` 是对的。

原因在监督进程（`session::supervise`）：从 v0.10.0（`94eb7bf`，2026-09-08 接入实例）起，拉起 Claude 时的配置目录只从实例里取。旧写法（`agent_node` + 节点上的 `claude_config_dir`）没有实例，这个目录就被覆盖成空。`--print` 和交互会话都经过这里，都受影响。后果是检查的是一个登录、实际跑的是另一个：拿 `claude_config_dir` 配第二个账号来省额度的人，花的是默认账号的额度。

修法：没有实例时用会话记录里的 `claude_config_dir`。新测试 `supervise_runs_claude_in_a_legacy_claude_config_dir` 让假 `claude` 记下它拿到的 `CLAUDE_CONFIG_DIR`，在旧代码上是 `unset`（红），修后是配置的目录。Codex 的旧写法请求本来就不许带配置目录（`validate_provider_request`），不受影响。之后的模拟用的都是带这个修复的发布构建（sha256 `f2502583…`），只放在两边的 `~/p114sim/bin/`，日用的 `~/.local/bin/ccnm` 没换。

那次误用日用登录的会话：没打过字，假模型一条请求也没收到；它在日用 `~/.claude.json` 里留下的 `lastCost` 是 0、token 全是 0，转录里只有 Controller 替它敲的一次 `/mcp reconnect`。我在信任提示上选了"信任"，日用 `~/.claude.json` 因此多了一条这个临时目录的信任记录，测完已经去掉（改之前在旁边留了备份），那份转录也删了。

## 3. 结果

| 步骤 | 看到什么 |
| --- | --- |
| `ccnm doctor sim --on a`、`--on b` | 都是"可以用了"，Claude 认证 `logged in via api_key`，远端 MCP 握手各自通 |
| `ccnm run sim --on a --detached`，假模型跑一轮工具 | 项目机器的项目目录里出现 `sim-a.txt`（"written on a"）；`exec_command` 的结果里 `pwd` 是项目机器上的项目目录；界面写 `API Usage Billing` |
| a 开着时，不在终端里 `ccnm run sim --on b --detached` | 退出码 33，`CCNM_E_POLICY`：`sim 正在 a 上跑，一个项目同一时间只能在一台上写`，后面是要敲的两条命令。不替人停 |
| a 开着时，`ccnm mcp probe sim --on b` | 退出码 33：项目机器以 coding 模式开这条连接时报 `workspace write guard is busy`。**两边不能同时写**，挡在起会话和写锁两层 |
| 让 a 的模型写交接，然后 `ccnm stop sim` | a 的会话目录里 `handoff.md` 正是从 `[ccnm handoff]` 那行起的部分；`ccnm handoff sim` 预览"…的交接，123 字节，下次起会话时会带上" |
| `ccnm run sim --on b --detached` | 打出"带上了 … 上一次会话的交接（123 字节）"；项目机器记下 `on = b`，`handoff.json` 标成已交 |
| b 上说第一句话 | 假模型收到的第一条主请求里有 `SessionStart:startup hook success: ccnm: this project's previous session, on the AI machine …, ended with the handoff below. … If the user's first message asks for something else, follow the user.` 和交接原文；b 会话目录里的 `carried.json` 已被钩子删掉。b 的工具同样写进项目机器的**同一个**项目目录（`sim-b.txt`，`pwd` 同上） |
| b 没写交接就 `ccnm stop sim`，再 `ccnm run sim --on a --detached` | 预览和起会话都说"对话记录（没写交接）（58 字节）"；内容只有 `[user] P114TOOL …` 和 `[AI] tool round done on b`，工具调用和输出都没带。回到默认那台，`on` 记录删掉 |
| a 上说第一句话 | 第一条主请求里是 `…ended without a handoff -- its login may have run out. Below is the end of that conversation … It is raw, not a summary … check the project itself before relying on any of it (git status, the files it names) …`，后面是那两句 |

## 4. 收尾

停了最后一个会话；`launchctl bootout` 卸掉两个模拟 Controller；停掉假模型；两份 tmux server 都已不在，没有残留进程。两边的 `~/p114sim/` 整个删了，日用 `~/.claude.json` 的那条信任记录和误建的转录目录也清了（见第 2 节）。日用 Controller 的 pid 测试前后一样，用户的四个会话都在、工具都通。证据（请求原文、假模型索引、两个 Controller 的日志）留在这次会话的临时目录里，没进仓库。

## 5. 模拟替代不了的

- **两台真不同的机器**：两份部署在同一台物理机上、同一个账号下，所以没覆盖不同的系统或 Claude Code 版本、第二台到项目机器的另一条 ssh 路径（包括它的密钥和 `known_hosts`），也没覆盖上一台关机或断网时取不到交接。
- **真实的第二个登录**：两份用的都是假 key。额度用完时模型写不出交接，所以带原始记录兜底；这一条只用"没写交接"模拟，没有真的用完额度。
- 提示里的机器名两台相同（第 1 节）。
- 终端里的 `[y/N]` 提问照旧只走了不在终端里的那条。
