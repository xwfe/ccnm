## 2. 三台换装

本机用核对过的包；fodelf 自己从 GitHub 下载、核两次 sha256、`controller install`；hpsrv 由本机 scp 给 root、核 sha256、`install -o ccrun`、由 ccrun 自己 `mv`。三台都用新文件加改名，临时目录用完删了。Windows 测试机没装（上次测完已清空）。

**会话没停、只换文件**：本机和 fodelf 上开着用户的 keex、xdo、ragcheck、shun（后两个有终端接着），换装前后 tmux 都在。本机这 4 个会话的 `mcp-serve` 是 10:57 起的，照旧跑老代码、攥着写锁，会话结束或工具重连后才换成新文件。

| | 本机（Runtime / Operator） | fodelf（Agent） | hpsrv `ccrun` |
| --- | --- | --- | --- |
| 之前 | `0d644fe` 的开发构建，报 0.21.1，`da2845d3…` | 同左，Controller pid 82126 | v0.21.0 `8feb86eb…` |
| 之后 | `ccnm 0.22.0`，`c1ed1acd…` | 同左；Controller pid 95472，`Aqua`，报 `listening: ccnm 0.22.0` | `ccnm 0.22.0`，`1b2c5509…` |

**doctor**（本机发起）：`ccnm`、`codingagent`、`gld`、`xshun` 四个"可以用了（2 项不查）"、退出 0，每个 2–4 秒。Runtime、Agent、Controller、反向 SSH 四行都报 0.22.0。`keex`、`ragcheck`、`shun`、`xdo` 各一项失败，都是远端 MCP 握手报 `workspace write guard is busy`：这 4 个项目的会话正开着、占着写锁，是预期，会话结束就好。

换完 `ccnm status` 里 4 个会话的工具都是"通"。

fodelf 的 Controller 日志里，今天 01:57 UTC（本机 10:57）有一次真实断网：先记了一条 keex `could not reconnect`（`ssh … connect to host` 失败），11 秒内 ragcheck、shun、xdo 三个依次 `reconnected`，再过 34 秒 keex 也接上了。这是 10-29 换上的 `0d644fe` 开发构建（P116）第一次在日常使用里起作用，不是测试；用户没动手。
