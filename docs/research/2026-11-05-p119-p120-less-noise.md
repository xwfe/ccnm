# P119、P120：少打扰（2026-11-05）

用户 2026-11-05 提了两处：ccnm 经常打出一堆"成功重连"；动不动就提示 handoff，交接内容又长。两处都进 1.0.0。

## P119：没人接着、模型也没在干活的会话，工具断了先不接

**为什么**：同日在项目机器上跑 `ccnm status`：keex 已运行 20 天，自动接回过 40 次；xdo 已运行 5 天，接回过 17 次。两个会话最近一次接回在同一时刻（3 小时 35 分前），两个当时都"没有终端接着"。说明不是误判，是项目机器睡眠或换网后 ssh 真断了，Controller 把每个开着的会话各接了一次。每接一次，Claude Code 都在对话里留下两行（`❯ /mcp reconnect ccnm`、`⎿ Successfully reconnected to ccnm`），ccnm 收不回来。

**做法**：Controller 看到工具断了时，有终端接着（tmux 的 `session_attached` 大于 0）或者模型正在干活（界面底下有 `esc to interrupt`），照 P116 接；都不是，就不问项目机器、不敲字，在 `reconnects.json` 里记下 `waiting_since`，`ccnm status` 那一行写"断了（没人接着，有人进来时接上）"。人用 `ccnm attach` 或 `ccnm <项目>` 进来时，照 P100、P116.3 先接通再进；直接 `tmux attach` 进来的，Controller 下一轮（最多 30 秒）看到有人就接。界面读不出来时当作空闲，代价是工具等人来，不会多敲字。

**代价**：没人接着的会话，模型停着时工具一直断着。模型刚开始干活（比如定时任务把它叫醒）时，第一次工具调用可能撞上断开，要等 Controller 下一轮（最多 30 秒）才接回。

**验证**（本机 macOS arm64，提交 `4f0f845`）：

- 新测试 5 条：`tui::working` 读界面底下那行，带颜色码也认；`watch_tools` 走一轮，没人接着、模型空闲时只有 `ps` 和抓一次屏，不连项目机器、不敲字；记下 `waiting_since`，清掉原来的退避，下一轮保留第一次的时间；没人接着但模型在干活时照接；status 那一句。
- 先红后绿：`the_watch_leaves_tools_down_while_nobody_is_there` 只用旧接口，放到改动前的代码（`f12d60e`）上跑是红的，第 4 条命令是去连项目机器，不是抓屏。
- `cargo fmt --check`、`cargo clippy --workspace --all-targets -- -D warnings` 干净；`cargo test --workspace --no-fail-fast` 1212 过、0 挂；`python3 -B scripts/ci_gates.py` 通过（Python 249 条、0 跳过）。
- 没做：真机（没有在 AI 机器上让项目机器睡一觉看效果）。

## P120：交接提醒由 ccnm 说一次，不再让模型反复提

**为什么**：P102 的做法是让模型自己提。压缩 1–2 次后，它在"事做完、转去做别的"时建议 `/clear`；第 3 次起"不等做完，到下一个能停的地方就停下写交接"。第 3 次之后这句话一直留在上下文里，没有"只说一次"，人不 `/clear` 接着干，模型到下一个能停的地方（跑完检查、提交了改动）又提一次。用户要求每个小改动都提交，等于每次提交都提一遍。交接又写在回复里，一写一大段。

**先量钩子能不能直接对人说话**（`docs/research/probes/p120-hook-notices.py`，本机 Claude Code 2.1.318，接本机假模型，HOME 是空临时目录，`sandbox-exec` 只放行本机出站，零额度）：

- SessionStart（startup、compact、clear）和 Stop 钩子往 stdout 打 JSON，`systemMessage` 显示在界面上：`⎿  SessionStart:compact says: …`、`⎿  Stop says: …`。
- SessionStart 的 `hookSpecificOutput.additionalContext` 进了下一次发给模型的请求，和纯文本 stdout 一样。
- 两种钩子的输入都带 `transcript_path`。`/clear` 之后 SessionStart 收到的是新对话的 id 和它的记录路径，上一段对话的记录在同一个目录里。

**做法**（`crates/ccnm-core/src/session/hook.rs`）：

- 压缩后只告诉模型压缩了几次。开头那段"怎么写交接"改成：人要交接、要换新对话时才写；不要自己建议换新对话，ccnm 会在压缩够了次数时告诉人。
- 从第 3 次压缩起，每次压缩完，钩子输出 JSON，给人一行：`ccnm：这段对话已压缩 3 次，早期细节只剩摘要。敲 /clear 开新对话，会带上这段的结尾（要完整交接，先说“写交接”）`。语言按 AI 那台配置里的 `[ui] lang`，没写就是中文。第 1、2 次照旧打纯文本，和 P120 以前一样。
- `/clear` 时：有交接带交接，并提示一行；没有交接而上一段压缩过 3 次以上，就从上一段的记录里读出结尾（P115 的 `conversation_tail`：人和模型说的话，不含工具调用和输出，最多 32 KiB），标明是原始记录，也提示一行；都不是就什么都不带，和以前一样。
- 回复以 `[ccnm handoff]` 那行结尾时，Stop 钩子给人一行：`ccnm：交接已记下。敲 /clear 开新对话接着做；在这里接着聊的话，这份交接就作废`。

**验证**（本机 macOS arm64，提交 `cc5778d`）：

- 单元测试：钩子模块 13 条全过，新加 3 条：模型听到的话里没有让它建议换新对话；压缩够了以后 `/clear` 带上一段的结尾，不够时不带；写下交接时有那一行，没写时不出声。原有的 4 条改成按新输出来读。`the_model_is_not_told_to_suggest_a_fresh_conversation` 只用旧接口，放到改动前的代码上跑是红的。
- 零额度端到端（同一个探针加 `--ccnm target/debug/ccnm`，真 Claude Code 2.1.318、真 ccnm 钩子、假模型）：第 1、2 次压缩界面上没有 ccnm 的行，第 3 次有；三次压缩后发给模型的请求里都没有旧的那句建议；没写交接时 `/clear`，界面说"把它最后的部分交给了这段新对话"，新对话第一条请求里带着上一段的原始记录（含 `after compact 3`）；让模型写交接后，界面有"交接已记下"那一行，`/clear` 后交接进了第一条请求，界面说"交接已经交给这段新对话"。跑完以后压缩那行在 160 列的终端里折了行，于是缩短了文字；缩短后的文字只跑了单元测试。
- `cargo fmt --check`、`cargo clippy --workspace --all-targets -- -D warnings`、Windows 目标的两条 clippy 干净；`cargo test --workspace --no-fail-fast` 1215 过、0 挂；`python3 -B scripts/ci_gates.py` 通过（Python 249 条、0 跳过）。
- 没做：真实模型（它会不会照新说明只在人要时写交接、写得够不够用）；在 AI 机器的真实会话上看那一行；交接仍写在模型的回复里，人要的时候才出现，没做成藏进工具调用（要加工具，显示效果也没量过）。
