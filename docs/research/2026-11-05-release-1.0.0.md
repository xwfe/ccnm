## 2. 换装前查配置

1.0.0 读不进写着 codex 实例的配置，所以先只读地查了三台：本机的 `config.toml`、fodelf 的 `config.toml` 和 `gldprobe.toml`（没有 `profiles.toml`）、hpsrv 上 `ccrun` 的 `config.toml`，都没有 `[agents.*]` 写 `provider = "codex"`，也没有 `exec_sandbox`、`codex_bin`。没改任何配置。fodelf 上 `~/.config/ccnm/agents/` 还在（以前 Codex 用的登录目录），没动。

## 3. 三台换装

本机用核对过的包；fodelf 自己从 GitHub 下载、核两次 sha256、`controller install`；hpsrv 由本机 scp 给 root、核两次 sha256、`install -o ccrun`、由 `ccrun` 自己 `mv`。三台都用新文件加改名，临时目录用完删了。

**会话没停、只换文件**：fodelf 上开着用户的 keex（已运行 20 天 13 小时）、xdo（5 天 5 小时），都没有终端接着，换装前后都在，工具"通"。本机这两个会话的 `mcp-serve`（pid 60643、59700）照旧跑老代码、攥着写锁，会话结束或工具重连后才换成新文件。

## 4. doctor

本机发起：`ccnm`、`codemirror-shiki`、`codingagent`、`gld`、`ragcheck`、`shun`、`xshun` 七个"可以用了（2 项不查）"、退出 0，每个 6–19 秒。Runtime、Agent、Controller、反向 SSH 四行都报 1.0.0。`keex`、`xdo` 各一项失败，都是远端 MCP 握手报 `workspace write guard is busy`（退出 33）：这两个项目的会话正开着、占着写锁，是预期，会话结束就好。

## 5. 没做的

- 发布包本身没有重跑零额度那一套：P118–P121 的零额度证据用的是同一批提交的开发构建（见各自记录），这次只换了文件、跑了 doctor 和 status。
- keex、xdo 两个开着的会话：钩子按绝对路径调 ccnm，换完文件立刻用上新的交接提醒（P120、P121）；80 万的压缩窗口写在会话起来时生成的设置文件里，要新起的会话才有。Runtime 侧还是老代码，要等会话结束或工具重连。
- Windows 包没下载、没装。
