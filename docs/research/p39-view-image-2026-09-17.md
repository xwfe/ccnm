# P39 `view_image`：把 Runtime 上的图片交给模型（2026-09-17）

环境：macOS arm64 开发机；Claude Code 2.1.273（只读打包代码，未登录）；Codex 0.154.0（本机假模型，`sandbox-exec` 禁非本机出站）。零模型额度，没上真机。

## 1. 结论

- 新增第九个工具 `view_image`，只读，`read` / `coding` 都有。按文件头认 PNG / JPEG / GIF / WebP，返回一段说明文本加一个 MCP `image` 块，数据是文件原样的 base64，上限 3932160 字节。
- ccnm 不缩放、不转码、不加图像处理依赖。
- `read_file` 读到这四种图片时指向 `view_image`。
- 真实 Codex 0.154.0 连真实 ccnm 调 `view_image`：图片以 `input_image` 进了下一轮模型请求，逐字节一致。

## 2. P39.1 实测

脚本和原始结果在 toexec 仓库 `evidence/v3-parity/media-surface/`（f7bf8aa、48b8b30），这里只写结论和它怎么决定了设计。

| 问题 | 结果 | 决定了什么 |
| --- | --- | --- |
| Codex 收到 MCP `image` 块（不开 Code Mode） | 变成 `input_image`，`detail: high`，原样转发 | 用 `image` 块 |
| Codex Code Mode（ccnm 受管会话的默认） | 工具结果是 JS 对象；模型脚本调 `image(r.content[1])` 后变成 `input_image` | 文本块放第一个、图片块放第二个；工具说明提一句 `image()` |
| Codex 收到 `resource` 块（blob 是 PNG 或 PDF） | 整个块 JSON 序列化成 `input_text`，base64 进上下文 | 不用 `resource` 块；PDF 不能这样发 |
| Claude Code 收到 `image` 块 | 支持的类型进缩放函数：超过 2000×2000 或字节预算就用 sharp 缩放 / 转 JPEG，再朝 512000 字节压一次；base64 上限 `maxBase64Size` 5242880 | 不在 Runtime 上缩放；上限取 5 MiB base64 = 3932160 字节原始数据 |
| Claude Code 收到不支持的图片类型或非图片 blob | 写到**跑 Claude Code 的那台机器**的磁盘上，模型只拿到那台机器上的路径 | 只发四种格式；别的格式报错而不是发出去 |
| 真实 ccnm 二进制 + 真实 Codex | `input_text`（`shots/red.png: PNG, 73 bytes`）加 `input_image`，解码后与文件一致 | 实现验证 |

Claude Code 那两行是读代码得出的，没有模型请求可看。原文摘录见 toexec 的 README。

## 3. 实现

- `crates/ccnm-core/src/mcp/image.rs`：`view_image` 先 `stat`（和 `read_file` 一样，避免打开 fifo 卡住），超限直接拒绝；读的时候最多读上限加一个字节，文件在 `stat` 之后变大也拦得住；文件头判断格式；SVG（开头 512 字节里有 `<svg`）单独提示用 `read_file`。
- 超限的错误消息给出在 workspace **里面**缩一份小图的命令——`view_image` 只能读 workspace 里的文件，写到 `/tmp` 的小图它读不到。
- `server.rs`：结果是 `[text, image]` 两块。
- 接线（P39.3 清单）：`session::MCP_TOOLS`、两份 `tools-list-*.json` 与 schema 的 `tool_name` / `read_tool_name`、schema 新增 `image_content` 并允许成功结果里出现它、新样例 `call-view-image-ok.json`、`provider_compat` 的放行清单差异、P11/P12 脚本和两份测试里的只读工具清单、`external_mcp` / `cli` / `mcp_read_file` 集成测试、中立客户端。
- `read.rs`：先看文件头是不是这四种图片，是就报"是图片，用 `view_image`"，再做原来的 NUL 检查。这是行为变更：原来一个前 8 KiB 没有 NUL 的 JPEG 会被当成乱码文本读出来。

## 4. 没验的、限制

- Claude Code 实际把图交给模型：没登录，没有请求可看，结论来自代码。
- 模型看图的效果、Code Mode 下模型会不会自己想到调 `image()`：没花模型额度。
- Codex 对大图：原样发出，服务端怎么计费、缩放本机看不到。上限按 Claude Code 定，对 Codex 来说 3.75 MiB 的图也会原样进请求。
- GIF 动图、带透明通道的 WebP：只发文件本身，Host 怎么处理没测。
- Linux：没跑。
- 门禁数字见 status.json 里 P39 的 evidence。
