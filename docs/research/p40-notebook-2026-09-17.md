# P40 Jupyter notebook：按 cell 读、按 cell 改（2026-09-17）

环境：macOS arm64 开发机；Claude Code 2.1.273（只读打包代码）；nbformat 5.11.1（临时 venv，只用来核对，不是 ccnm 的依赖）。零模型额度，没上真机。

## 1. 结论

- 第十个工具 `read_notebook`（只读）：cell 和输出渲染成文本，输出里的 PNG / JPEG 作为 MCP `image` 块按位置插入；按 cell 边界分页。
- `apply_patch` 加 op `edit_notebook`：`cells` 列表按顺序应用，字段和语义照 Claude Code 的 NotebookEdit，和其他文件一起原子提交。
- `read_file` 读 `.ipynb` 的结果不变，只多一条提示。
- 写回的文件是 nbformat 的写法：真实 nbformat 5.11.1 校验编辑后的文件合法，重写后逐字节一致。

## 2. P40.1 实测

### 2.1 原生行为（Claude Code 2.1.273 打包代码）

**Read 渲染 notebook**（摘录）：每个 cell `<cell id="${id}">…源码…</cell id="${id}">`，非代码 cell 加 `<cell_type>`，非 Python 加 `<language>`；id 是 `e.id ?? "cell-" + 序号`。输出：`stream` 取 `text`；`execute_result` / `display_data` 取 `text/plain`，另把 `image/png`、`image/jpeg` 解出来作为图片块；`error` 拼成 `${ename}: ${evalue} ${traceback}`（不去颜色码）。输出太大时换成一句"用 jq 读 `.cells[N].outputs`"。

**NotebookEdit**（摘录，变量名是打包后的）：

```js
Ke = cells.findIndex(c => c.id === cell_id); if (Ke === -1) Ke = 解析 "cell-N" 得到的 N
if (edit_mode === "insert") Ke += 1                  // 插在 cell_id 后面；没给 cell_id 时 Ke = 0
if (nbformat > 4 || nbformat === 4 && nbformat_minor >= 5) { insert 时 id = 随机串.slice(0, 8) }
delete:  cells.splice(Ke, 1)
insert:  markdown → {cell_type, id, source, metadata: {}}
         code     → {cell_type, id, source, metadata: {}, execution_count: null, outputs: []}
replace: cell.source = new_source; 若是代码 cell：execution_count = null, outputs = []
         若给了 cell_type 且不同：cell.cell_type = cell_type
写回：JSON.stringify(notebook, null, 1)
```

参数说明原文：`cell_id` —— "When inserting a new cell, the new cell will be inserted after the cell with this ID, or at the beginning if not specified"；`cell_type` —— "If using edit_mode=insert, this is required"；`edit_mode` —— "replace, insert, delete. Defaults to replace"。

### 2.2 nbformat 的写法

Python 标准库 `json.dumps(sort_keys=True, indent=1, ensure_ascii=False)` 加结尾换行生成样例 `tests/fixtures/notebook/analysis.ipynb`（生成器 `make_notebook.py` 同目录）：五个 cell，含中文 markdown、stream 输出、一张 PNG 的 display_data、execute_result、带终端颜色码的 error、未运行的空 cell。

`serde_json`（ccnm 没开 `preserve_order`，对象键按名字排序）读进来、用一个空格缩进写出去，和样例逐字节一致（单元测试 `an_untouched_notebook_is_written_back_byte_for_byte`）。

之后用真正的 nbformat 5.11.1 核对（`tests/fixtures/notebook/check_with_nbformat.py`，结果见第 4 节）。

## 3. 实现与决定

- **不改 `read_file`。** v3 方案原先写的是"`read_file` 遇到 `.ipynb` 按 cell 渲染"。实现时改了：`read_file` 返回 JSON 文本已经是冻结契约里的行为，有人照着它用 `update` 改 notebook，换成 cell 视图这些改动就对不上。所以另立工具，`read_file` 只在提示里指过去。
- **和原生的两处不同**：改类型时去掉新类型不允许的键——nbformat 的 schema 不许 markdown cell 有 `outputs` / `execution_count`，Claude Code 会留下空的；`source` 存成行数组（nbformat 的习惯），原生存成一个字符串。两种 nbformat 都认。
- **比原生严格的地方**：`replace` 找不到 cell 时报错并列出所有 id（原生在序号等于 cell 数时悄悄改成插入）；`replace` / `delete` 必须给 `cell_id`（原生不给时作用在第一个 cell）。
- **不执行 cell、不渲染 HTML / LaTeX / SVG**，traceback 去掉终端颜色码。
- **上限**：文件 16 MiB（和 `apply_patch` 能编辑的上限同一个常量）；一次 32 KiB 文本、单个输出 4 KiB、8 张图且合计不超过 `view_image` 的上限——Claude Code 把每张图按 1600 token 算，MCP 结果上限 25000 token。

## 5. 没验的

- 在 Jupyter / VS Code 的界面里打开编辑后的文件（schema 和写法用 nbformat 核对过，界面没开）。
- VS Code 自己保存的 notebook：它的键顺序和缩进可能不同，ccnm 按文件原来的缩进宽度写、键按名字排序，第一次编辑可能带来格式上的整文件改动。
- 元数据里的浮点数：Python 写 `1e-05`，这里写 `1e-5`。
- 模型会不会用这两个工具、Linux 上跑：没验。
