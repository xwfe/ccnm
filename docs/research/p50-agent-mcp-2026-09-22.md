# P50：Agent 机器上装好的 MCP server 交给会话（2026-09-22）

零额度，macOS arm64。实测脚本和结果在 toexec 的 `evidence/v4-mcp/agent-mcp/`；共用机制在 toexec 的 `toexec-mcp` 0.2.0（新加 `kept`、`sse`，gld 同用）。这里只记 ccnm 按它做了什么决定。怎么开关见[配置说明](../configuration.md#agent_mcp)，怎么用见[使用说明](../usage.md#agent-机器上的-mcp-server)。

## 起因

toexec v4 方案第 4 步：ccnm 受管会话接 Agent 机器上装好的 MCP server。用户 2026-09-22 的要求是 ccnm "默认全开"、不要了能整块删、共用代码进 toexec；方案里这一步当初定的是"只放网络类"。用户说"push, then continue step 4"。

## 先量的

Claude Code 2.1.278、Codex 0.154.0（受管会话钉的版本）和 0.155.1，假模型，启动参数照 ccnm 拼。

| 问题 | 结果 | 对设计的影响 |
| --- | --- | --- |
| 把 server 直接写进 Claude 的 `--mcp-config`，调得通吗 | 通；print 模式下要在 `settings` 里 allow（server 级的 `mcp__<名字>` 就行），HTTP 的也能直接连 | 技术上最简单的路是通的，但看下一行 |
| 大结果到模型那里剩多少 | **Claude：超过约 50 000 字符就存到 Agent 磁盘、只给 2 KB 预览要模型用 `Read` 读**——受管会话没有 `Read`。50 000 字节原样，52 000 字节只剩预览。**Codex 指定模型时（`gpt-5.1-codex`）只留约 12 KB**，头尾各一半；Code Mode 留约 40 KB | 不能直接写进原生配置；由 ccnm 自己转、自己切页 |
| 这些线能不能调 | Claude：工具定义里带 `_meta["anthropic/maxResultSizeChars"]`，200 000 时 150 000 字节原样到达。Codex：`-c tool_output_token_limit=20000` 后 81 000 字节原样到达（0.154.0 和 0.155.1 一样）；对 Code Mode 不起作用 | ccnm 自己的工具也撞这两条线，一起修（见下） |
| Codex 直接写进去要什么 | `approval_policy="never"` 下不写 `default_tools_approval_mode="approve"` 每次都被拒 | ccnm 转的话沿用它给 `ccnm_agent` 的写法 |

## 决定

| 问题 | 决定 | 为什么 |
| --- | --- | --- |
| 怎么交给会话 | P48 起就在 Agent 上的 `ccnm internal agent-skills`（到模型那里是 `mcp__ccnm_agent__*`）多两个工具：`call_mcp_tool`（和 Runtime 上的同名、同参数、同用法）和 `read_mcp_result` | 结果由 ccnm 切页，不撞客户端的线；模型看到的是一个工具加一串名字，不是每个 server 的全部工具（开发机上 playwright 一家 21 KB） |
| 默认给哪些 | 别的机器上的 HTTP 地址默认给；这台机器上跑的（程序、`127.0.0.1` 上的服务）要 Agent 的 `[agent_mcp] local` 点名 | 本机跑的能读写 Agent 的磁盘、跑命令、用这个账号的 ssh 连 Runtime，而远端会话特意关了 Claude / Codex 自带的文件和 shell 工具；哪个 server 只联网从配置上看不出来（context7 和 Filesystem 都是 `npx` 起的），所以按从配置分得清的那一刀切，不猜 |
| workspace 有没有一票 | 有：`agent_tools` 多一个值 `mcp_servers`，默认开 | 远端 server 收得到模型发给它的东西，和 `web_fetch` 一样担风险的是项目；默认开是用户"默认全开"的决定。**这和 `web_fetch` 默认关矛盾**，文档照实写，要收紧就去掉它 |
| HTTP 怎么连 | 系统的 `curl`，一条消息一个进程；地址和请求头写进只有本账号能读的文件，`curl -K` 读 | ccnm 没有 HTTP 客户端，P49 刻意没带 TLS；默认给的恰好全是 HTTP 的。exa 的 key 在地址里，不能上命令行 |
| 长结果 | 超过 32 KiB 的留在这个进程的内存里（30 分钟、单条 16 MiB、总共 64 MiB），`read_mcp_result` 按 32 KiB 一段读 | Agent 上没有 `read_output`；32 KiB 在两个客户端里都能完整到达（Codex 靠下面那个修复） |
| server 的环境 | 客户端给 `ccnm_agent` 什么就给什么，去掉 Agent 登录变量（`ANTHROPIC_API_KEY`、`CODEX_HOME` 这些）和 `SSH_AUTH_SOCK`，加配置里的 `env`；`${VAR}` 查什么都行 | 这些配置是账号自己的，不是项目的；`GITHUB_TOKEN` 这类原生直接起也拿得到 |
| 配置里自己关掉的 | 不给，写明"turned off in …"；P49 的 Runtime 那边也一样改了 | Codex 的 `enabled = false`、JSON 的 `"disabled": true`：装它的那个客户端也不会起它 |
| 开关 | Agent 自己的 `[agent_mcp]`：`enabled`、`local`、`hidden` | 在 Agent 上以这个账号跑什么，是这台机器的决定 |

**共用代码**：长结果留着分段读和拆 SSE，gld 第 2 步各写过一份，这次 ccnm 也要，搬成 `toexec-mcp` 0.2.0 的 `kept` 和 `sse`，gld 改用它们。一次调用的步骤（清单、列工具、调用、整理结果）和 P49 是同一份：`mcp/relay.rs` 里抽成 `call` 加一个 `Side`，Runtime 和 Agent 各给自己那几样（读哪些配置、怎么起、哪些不能转、长结果放哪）。这一块没进 toexec：gld 的工具形状不一样（三个工具），用不上。

## 附带修掉的两处（不止第 4 步）

量出来的两条线，ccnm **已有的**工具也撞：

- **Codex 12 KB**：`read_file` 默认一页 32 KiB、`read_output` 默认 16 KiB、P49 的 `call_mcp_tool` 一次 32 KiB，在指定了模型的 Codex 会话里中间都会被砍掉，模型却照着结果末尾的说明从后面接着读。对照实验里还看到更糟的：P50 的第一段被砍时，**末尾那句"接着读"的说明整条被丢**（`[omitted 1 text items ...]`）。修法：Codex 会话加 `-c tool_output_token_limit=20000`（放在 MCP 那段参数后面，0.154.0 实测 fixture 对照的那段 argv 不变）。提交 `1965d44`。
- **Claude 5 万字符**：`read_file`、`load_skill` 一页最多 64 KiB，`call_mcp_tool` 的工具表最多 64 KiB，会被存盘只给预览。修法：这三个工具（Agent 上的 `load_skill`、`call_mcp_tool` 也是）带 `_meta["anthropic/maxResultSizeChars"] = 200000`。`tools/list` 因此超了 16 KiB 预算 84 字节，把 `apply_patch` 两个参数说明里"按顺序应用"的长解释压成一句、去掉漏给模型的内部编号，回到 16 293 字节。提交 `198a9dd`。

所以 P49 记录里"大结果 32 KiB 一段、经 `read_output` 读全"那句，当时只在 Claude 上成立，Codex 只测了一个小结果。

### 查出来修掉的：`curl` 的请求文件留在盘上

真实会话结束后，fodelf 的 `$TMPDIR` 里留着 `ccnm-curl-<pid>-0`，里面就是 `-K` 请求文件——地址和请求头，换成 exa 那种 key 写在地址里的 server，key 就留在了盘上（目录 0700、文件 0600，只有本账号读得到）。本机前一天的零额度实测也留下过一个。

原因：清理挂在"客户端关 stdin"那条路上。实测（`claude_exit_signals.py`）Claude Code 2.1.272 和 2.1.278 退出时对 stdio server 都是先发 SIGINT、100 ms 后 SIGTERM、SIGINT 之后约 0.4–0.5 秒强杀，**stdin 从头到尾不关**，那条路一次都走不到。

修法（`828e1f5`）：目录只活一次 `curl`，发请求前建、`curl` 结束就删。没加信号处理：SIGKILL 接不住，关连接时那个 DELETE 最多等 2 秒也来不及。对照（`ccnm_claude_exit`，假模型）：修之前会话结束留一个目录，修之后不留，本机 2.1.278 和 fodelf 上的 2.1.272 都是。`ccnm_agent` 起的 stdio server 两种情况下都跟着没了：`ccnm_agent` 一死它们的 stdin 就断，自己退出。

### 还是没验的

- Codex 当 Agent 的受管会话经 SSH（fodelf 没装 Codex），以及 Codex 会话里真实模型会不会用；
- 真实模型碰上超过 32 KiB 的结果会不会照着说明用 `read_mcp_result` 读下去（这一轮的结果都小）；`[agent_mcp] local` 点名的本机程序类 server 在真机上；
- 慢网络上的大结果：`~/.claude.json` 里的 server 没有单独的调用超时可调（只有 Codex 配置的 `tool_timeout_sec` 认），会撞 60 秒；
- Windows。
