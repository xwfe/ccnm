# P7.5：冻结前修掉的两处行为，和两条只能写进声明的事实（2026-09-10）

Machine Protocol `ccnm.machine/1` 在这一轮冻结。冻结之前先落了两个行为修正——都是真机验证暴露出来、
不适合带进 v1 语义的东西——另外两条网络策略层的事实只能写进安全边界，ccnm 改不了。

## 一、`ccnm stop` 对已结束的会话现在是幂等的

**之前**：会话自己跑完之后再 `ccnm stop`，退出码 **3**，报
`CCNM_E_NOT_READY: no verifiable selected session is running`。

话没说错，但后果是实的：清理脚本无脑调一次 stop 就拿到非零退出，看起来像清理失败；`--print` 跑完的
会话根本没法被"成功地"停一次。Claude 和 Codex 两轮真机都是这个表现，说明它是控制面的性质，不是某个
provider 的毛病。

**现在**：没有会话在跑时退出码 **0**，报告里 `killed` 为 false：

```text
$ ccnm stop p7codex
nothing to stop: ccnm-p7codex was not running
```

### 幂等不等于永远不报错，这是关键

旧代码把两种完全不同的情况压成了同一句话，改的时候把它们拆开：

| 情况 | 之前 | 现在 |
| --- | --- | --- |
| 没有终端在跑 | `NOT_READY` rc=3 | **rc=0，`killed=false`** |
| 终端在跑，但认不出是不是你选的那个会话 | `NOT_READY` rc=3，文案同上 | 仍然 `NOT_READY`，文案改成 `a terminal is running for this workspace but carries no verifiable ccnm session identity` |
| `--session` 指了一个本机没有记录的 id | `no session <id> on this machine` | 不变 |

第二行是**故意留着的失败**：那道检查存在的理由是不去杀别人的会话，跟幂等无关。第三行同理——
"不知道这个会话"和"知道它已经结束"是两件事，混为一谈就是拿沉默当成功。

顺带补上一处记账：被点名的会话如果终端已经没了却没留下终态，现在会在返回前补写终态失败记录。
不补的话那条记录永远没有 outcome，`status` 会一直把它报成 unknown。

三条离线测试钉住这三行（`crates/ccnm-core/tests/session_identity.rs`），真机复验见第四节。

## 二、Code Mode 改成按模型能力开，代价写进了支持矩阵

**之前**：ccnm 无条件传 `--enable code_mode_only`。

**问题**：Code Mode 是 Codex 的 under-development 特性，**模型可以不支持它**。`gpt-5.3-codex-spark`
就不支持，Codex 启动时自己会说 `model … does not advertise Code Mode support`。硬开的后果在
[Codex parity 记录](p7-codex-parity-2026-09-10.md)里有实例：模型在包了一层的工具下只试了一次
`exec_command`、参数形状还写错，被拒之后直接回 `DONE`——**报告成功，文件一个字没写**。

**现在**：只对实测过 Code Mode 的模型开。目前那就是"不写 `model`"的 CLI 默认模型——所有 fixture 都是
在它上面采的。Rust 里是 `CODE_MODE_MODELS`，采集脚本里有同名的一份，两边必须一起改。

### 为什么不能在启动前问一句

问不到。`codex doctor --json` 报的是特性开关开没开，不报模型支不支持：

```text
/checks/config.load/details/feature flag overrides = code_mode=true, code_mode_only=true
/checks/config.load/details/model                  = gpt-5.3-codex-spark
```

不匹配只在会话跑起来之后，以事件流里一条 `item.completed` / `type: "error"` 的告警出现。所以这只能是
一张**实测表**，跟版本 pin 一样。

### 关掉 Code Mode 的代价，量了再写

新增 `tool-surface` 采集模式（只问模型看得见哪些工具，不让它动手）。关掉 Code Mode、用 spark 测，
模型报回来的顶层工具是：

```json
["functions.list_mcp_resources","functions.list_mcp_resource_templates",
 "functions.read_mcp_resource","functions.request_user_input",
 "functions.apply_patch","tool_search.tool_search_tool","multi_tool_use.parallel"]
```

**`functions.apply_patch` 在里面**——那是 Codex 自带的 patch 工具。开着 Code Mode 时它是不存在的
（[2026-09-07 探测](codex-provider-probe-2026-09-07.md)测到 `typeof tools.apply_patch == "undefined"`），
靠的是 `features.code_mode.excluded_tool_namespaces` 那条过滤。关掉之后，拦住它去写 Agent 本机的
**只剩只读 sandbox 一层**。

这不是纸上推演，真机上模型真的去试了：

```text
ERROR codex_core::tools::router: error=patch rejected: writing is blocked by
      read-only sandbox; rejected by user approval settings
```

然后它才改用 ccnm 的 `apply_patch`，写到了 Runtime 的工作树里，属主 `ccrun`。

所以这是一次**真实取舍，不是等价替换**，[支持矩阵](../support-matrix.md)里那张表把两种配置的验证范围
分开写了：要窄的那一栏就用默认模型。

试过但**无效**的路：`-c tools.apply_patch=false` 和 `disabled_tools` 的几种写法，配置能加载
（`codex doctor` 报 `ok config loaded`），实测工具面一点没变——被静默忽略的键，不要拿它当开关。

### fixture 跟着重测了

旧的 `seven-tools` 是 Code Mode 硬开着采的，那个启动 ccnm 已经不再产生。重测之后：

- `seven-tools.{json,stdout}` —— 现在实际会发的启动。**七个工具一次全过**（硬开 Code Mode 那次
  `apply_patch` 猜了四次），Agent 侧哨兵一字未动。
- `seven-tools-code-mode.{json,stdout}` —— 旧的那次留着，它是这次改动的证据，也是"每次拒绝都说清缺
  什么"那条契约测试的数据。
- `tool-surface.{json,stdout}` —— 上面那份工具面。

另加一条测试 `the_measured_fixture_records_the_launch_this_adapter_builds`：把 fixture 记的 argv 和
provider 真正构造的 argv 从 `exec` 一路比到 MCP 接线为止。**这正是这次差点漏掉的东西**——Code Mode 开关
一改，旧 fixture 记的 argv 当场就不再是 ccnm 会发的了，而只断言一两个 flag 的测试看不出来。

`runtime_file` 是 `CCNM_RUNTIME_PATCHED_7319\n\n`，两个换行：模型把不含换行的哨兵换成了带换行的新值，
原来那个换行还在，ccnm 写的就是收到的那条 edit。两次独立测量都这样。采集脚本的严格判据因此不通过，
**保留原样，不为了变绿放宽判据**。

## 三、两条只能写进声明的事实

用户拍板：这两条都不在 P7.5 改，只写清楚边界。**不动 Tailscale ACL、防火墙或 root 策略。**

### 1. `ccrun` 可经 Tailscale SSH 出站

写进[生产安全](../production-safety.md)的正式声明，两句话不能合并成第三句：

- **ccnm 不提供 egress isolation，也不声称提供**；
- **ccnm 保证的是它自己**——控制链不要求 Runtime Executor 持有任何出站凭据，正常路径上不发起出站连接，
  这一条有真机证据（会话活着时 `ccrun` 名下只有入站 `sshd-session` 和它的 `mcp-serve` 子进程）。

### 2. Agent Node 允许无传统凭据的 root 登录

`ssh root@<host>` 由 Tailscale SSH 按 tailnet 身份放行，不要密码也不要密钥。ccnm 造不成也管不了，但它
足以让全部身份隔离失去意义——能拿到 root 的人不需要绕过 `ccrun`。**列为部署环境的高权限风险，不计入
ccnm 的安全保证**；生产部署自己在 tailnet ACL 或 OS 层关掉，`ccnm doctor` 查不到它。

## 四、真机复验（最小）

复用 P7.3 Codex 那套环境（Agent=xdwmbp/`bing`，Runtime Executor=xdwmbp/`ccrun`），两端换成本轮构建
`sha256 51c5c73e83ecbb3613ca13ed378ddeab87e080ac3e57ff9a5bf16e5a0d70bc20`，被替换的那份留在各自
`~/.local/bin/ccnm.pre-p75`。Controller 重启 31396 → 1531。

## 五、冻结

`ccnm.machine/1` 冻结。依据是两个 provider 各跑通过一次真机双机闭环并与人类 CLI 对照
（[Claude](p7-real-machine-2026-09-10.md)、[Codex](p7-codex-parity-2026-09-10.md)），加上本轮这次最小复验。

冻结的是**契约**：往后加字段、加方法、加非终态可以；删字段、改语义、加终态要升 `ccnm.machine/2`。
实现比契约少的那几条（interactive、输出分页、结果过期、`-32008` 从不返回）原样留在
[协议说明](../protocol/README.md)的清单里——补上它们属于加法，不违反冻结。

## 六、这一轮没有验的

- Codex 的 interactive 与 Ctrl-D；Codex 的完整项目 dogfood。
- 默认模型（额度 9/15 才恢复）：Code Mode **开**着那条路径这一轮没有在真机上重跑，它的证据仍是
  0.153.4 那批 fixture 和 2026-09-07 的探测。
- egress / 网络策略：只写了声明，没有逐项验证，也没有改任何 ACL。
- 只在 macOS，只有这一套同机双身份拓扑。
